# SKILL_SPEC — 블로그 글 작성 스킬 파일 기준 (naver · velog · tistory)

**왜 필요한가**: 제품의 실체는 이 파일이다. 사이트가 좋아도 스킬이 실패하면 가설 검증이 끝난다.

| 항목 | 기준 |
| --- | --- |
| 구조 | `blog-writer-naver/SKILL.md` (폴더 안에 파일) |
| 입력 | `/blog-writer-naver [내용]` 한 줄만으로 동작 |
| 단계 | 내용 확인 → 글 초안 작성 → (브라우저 연결 시) 네이버 에디터에 입력 |
| 실패 시 | 브라우저 도구가 없으면 초안만 출력하고 "자동 게시에는 브라우저 연결이 필요합니다"라고 안내 |
| 수정 쉬움 | 말투·글 길이·금지어를 파일 상단 한곳에 모아 비개발자도 고치기 쉽게 |
| 안전 | 개인정보·계정 정보를 파일에 넣지 않고, 게시 전 사용자 확인을 거침 |

## 벨로그·티스토리 (`blog-writer-velog`, `blog-writer-tistory`)
네이버 스킬과 구조·입력·안전 기준이 같다. 다른 점만 적는다.

| 항목 | 기준 |
| --- | --- |
| 대상 | 개발 글만이 아니라 기획 노트, 업무 회고, 프로젝트 기록도 쓴다(기획자 등 비개발자 사용자 고려) |
| 글 형식 | 마크다운으로 초안을 쓴다. 대화창에 먼저 보여 주고 확인받는다 |
| 벨로그 | 에디터가 마크다운이라 그대로 입력한다 |
| 티스토리 | 글 작성 방식이 마크다운일 때만 입력한다. 아니면 입력하지 않고 바꾸는 방법을 안내한다. 화면 이름·바꾸는 방법은 `[확인 필요]`(실제 화면에서 확인 후 확정) |
| 지어내지 않기 | 사용자가 말하지 않은 사실·수치·사례를 쓰지 않고 `[확인 필요]`로 남긴다 |
| 내부 정보 | 회사 내부 정보·개인정보가 보이면 글에 넣기 전에 확인한다 |

## Word·한글 (`doc-writer-word`, `doc-writer-hangul`)
분류는 `문서 작성`. 안전·지어내지 않기 기준은 위와 같다.

| 항목 | 기준 |
| --- | --- |
| 하는 일 | 보고서·기획서·회의록·공문 초안을 쓰고 Word·한글에 붙여 넣기 좋게 정리한다 |
| 결과 | 대화창에 초안을 출력한다. 파일 저장은 환경에 따라 다르므로 단정하지 않는다 |
| Word | `.docx` 저장 가능 여부는 `[확인 필요]` |
| 한글 | `.hwp`는 만들지 않는다고 알리고 붙여 넣는 방법을 안내한다. 세부 방법은 `[확인 필요]` |
