# 콘텐츠 제작 명세 · 친구 테스트 계획

## A. 콘텐츠 제작 명세
**왜 필요한가**: 핵심 가치가 "안내"인데 스크린샷·쇼츠는 개발보다 오래 걸리고 재촬영이 잦다. 찍기 전에 목록을 정해두면 한 번에 끝난다.

| 자산 | 내용 | 분량 |
| --- | --- | --- |
| 결과물 예시 | 생성된 글 + 네이버 게시 결과 화면 | 스크린샷 2장 |
| 설치 쇼츠 | 다운로드 → 숨김 폴더 열기 → 폴더에 넣기 → 실행 (맥/윈도우 각각) | 각 30~60초, 자막 필수 |
| 안심 안내 | 메모장으로 SKILL.md 열어 보여주기 | 스크린샷 1장 |
| 커스텀 | 문장 하나 수정 후 결과가 달라지는 비교 | 스크린샷 2장 |

쇼츠 규칙: 음성 없이 자막만으로 이해되게, 마우스 클릭 위치 강조, 한 영상에 행동 하나.

## B. 친구 테스트 계획
**왜 필요한가**: 성공 여부는 코드가 아니라 "혼자 성공했는가"로 판정된다. 관찰 방법을 미리 정해야 결과가 데이터로 남는다.

- **대상**: 코딩 안 하는 지인 3명 이상, Claude 유료 구독자 우선
- **방식**: 링크만 전달, 옆에서 보지 않기, 가능하면 화면 녹화 요청
- **과제**: "이 사이트를 보고 블로그 글 초안 하나 받아보세요"

| 기록 항목 | 예시 |
| --- | --- |
| 완료 여부 | 초안까지 / 게시까지 / 중도 포기 |
| 소요 시간 | 분 단위 |
| 막힌 지점 | 경로 못 찾음, 명령어 안 나옴 등 |
| 한마디 | "별거 아니네" 반응이 있었는지 |

판정은 PLAN의 성공 기준(3명 중 2명 이상, 10분 이내)을 따른다.
