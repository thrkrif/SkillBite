# 해외 레퍼런스 조사: 상세 화면(/skills/:id)

조사일: 2026-10-31. 방법: WebFetch로 각 페이지의 텍스트를 읽고, 막힌 곳은 WebSearch로 보충했습니다.

**한계(꼭 읽어 주세요)**: 이 도구는 페이지 글자만 뽑아 요약해 줍니다. 그래서 글꼴, 색, 여백 수치, 본문 폭(px), 실제 화면 모양은 확인하지 못했고 "미확인"으로 적었습니다. 요약 도구가 한 번 더 걸러 준 내용이라 세부가 빠졌을 수 있습니다. npm 패키지 페이지(403)와 GitHub Marketplace 일부, Zapier 앱 페이지(개발자용 텍스트만 나옴), Notion 템플릿(설명·미리보기가 비어 있음), Gumroad(제목만 나옴)는 직접 근거가 약합니다. 문구는 요약만 적었습니다.

---

## 1. Raycast Store 확장 상세 (예: Color Picker)

1. 상단: 이름과 한 줄 소개, 그 옆에 "Install Extension" 버튼(Raycast 앱을 바로 여는 링크)과 공유 버튼. 만든 사람 이름과 설치 수가 같은 줄에 있음.
2. 설치/사용: 별도 설치 설명 없이 버튼 한 번이 전부. 본문 안에 주요 기능 목록과 "활성화 방법" FAQ가 있음.
3. 신뢰: 전용 구역은 없음. 설치 수, 기여자 목록, 공개 소스(GitHub) 링크, 버그 신고 링크가 신호 역할. 권한·개인정보 설명은 미확인(없는 것으로 보임).
4. 결과물: 스크린샷 갤러리 6장(캡션 없음, 내용 미확인).
5. 조건: 지원 OS(macOS, Windows)만 표시. 최소 버전은 없음.
6. 구조: 탭(Overview, Commands, Version History) + 본문 + 사이드바(분류, 소스, 신고, 기여자, "함께 보는 확장"). 본문 폭 수치는 미확인.
7. FAQ: 본문 맨 아래쪽에 3문항.
8. 하단 반복 버튼: 없음(푸터만).
참고: 버전 기록 35건에 날짜가 있어 "관리되고 있다"는 증거가 됨.

## 2. VS Code Marketplace 확장 상세 (예: Prettier)

1. 상단: 이름, 게시자, 설치 수, 별점과 개수, "Free" 표시, 한 줄 소개. 바로 아래에 "Installation" 박스(명령을 복사하는 방식)와 "More Info" 링크.
2. 설치/사용: 상단 박스에 복사 가능한 한 줄 명령. 사용법은 긴 본문(README)에 있음.
3. 신뢰: 게시자 이름, 설치 수, 리뷰 수. 인증 배지는 추출 글에 없음(미확인).
4. 결과물: 이 페이지는 스크린샷 구역이 보이지 않음.
5. 조건: 전용 구역 없음. 지원 언어 목록과 버전 설명이 본문에 섞여 있음.
6. 구조: 탭 4개(Overview, Version History, Q&A, Rating & Review). 사이드바는 글로는 확인 안 됨(미확인).
7. FAQ: 없음. 본문 안 "Troubleshooting"이 대신함(흔한 오류 메시지 위주).
8. 하단 반복 버튼: 없음.

## 3. GitHub Marketplace 액션 상세 (Checkout)

1. 상단: 경로(Marketplace > Actions > Checkout), 제목, 한 줄 소개, 버전 선택 버튼과 별 버튼. 별도 "설치" 버튼은 없음.
2. 설치/사용: 곧바로 복사해 쓰는 코드 블록 한 개, 그 아래 "Scenarios"로 상황별 예시.
3. 신뢰: "Verified" 항목(GitHub가 만든 곳을 직접 확인했다고 표시), 기여자 수, 이슈·PR 수, 소스 코드, 보안 정책, 신고 링크가 한 구역에 모여 있음.
4. 결과물: 스크린샷 없음. 코드 예시가 그 역할.
5. 조건: "권장 권한"(`contents: read`) 블록. 실행 환경 요구 사항은 버전별 변경 기록 안에 있음.
6. 구조: 본문 + 사이드바(소개, 인증, 태그, 기여자, 자료 링크). 변경 기록(v7, v6…)이 본문에 길게 이어짐.
7. FAQ: 없음.
8. 하단 반복 버튼: 없음.

## 4. npm 패키지 페이지

페이지 직접 조회는 403으로 막혔습니다. npm 공식 문서에서 "README가 패키지 페이지에 그대로 표시된다"는 것만 확인했고, 설치 명령 위치·사이드바 구성은 **미확인**입니다. 근거로 쓰지 않습니다.

## 5. Zapier 앱 연동 페이지 (Slack 등)

조회된 내용이 개발자용 텍스트(연동 방식, 인증, 작업 목록)뿐이라 일반 사용자용 화면의 버튼, 템플릿, FAQ, 하단 버튼은 **미확인**입니다. 확인된 것은 인증 방식(OAuth)을 한 줄로 밝힌다는 점뿐입니다. 근거로 쓰지 않습니다.

## 6. Notion 템플릿 상세 (Weekly Planner)

1. 상단: 제목, 보기 버튼 하나("View template"). 설명과 미리보기 이미지는 추출되지 않음(미확인).
2. 신뢰: 만든 사람 이름과 그가 올린 템플릿 수, 연락·판매 링크, 평점과 평가 수가 보임. 가격은 확인 안 됨.
3. 구조: 아래에 "같은 제작자의 다른 템플릿", "비슷한 템플릿", "관련 글" 순서.
4. 사용법, FAQ, 포함 내용: 없음. 갱신일 표시는 오류로 보이는 값("56년 전")이었음. 오래된 날짜나 잘못된 날짜 표기는 오히려 신뢰를 깎는 예시.
5. 조건 표기, 하단 반복 버튼: 미확인.

## 7. Gumroad 상품 페이지

페이지 직접 조회는 제목만 나왔습니다. 검색으로 얻은 것은 제3자 블로그 설명뿐이라(위 커버 이미지가 위쪽에 크게 놓인다, 설명란에 판매 문구와 이미지를 넣는다 정도) **공식 근거로는 미확인**입니다. 평점 기능이 있는지도 자료마다 말이 달랐습니다. 근거로 쓰지 않습니다.

## 종합

실제로 읽은 곳은 Raycast, VS Code, GitHub 3곳입니다(Notion은 부분). 이 셋에서 공통으로 보인 모양은 다음과 같습니다.
- 상단에 이름, 한 줄 소개, 만든 곳, 행동 한 가지가 모여 있음.
- 사용법은 "복사해서 바로 쓰는" 짧은 블록으로 상단 가까이에 둠(VS Code, GitHub).
- 신뢰는 평점이 아니라 만든 곳, 소스 공개, 변경 기록의 날짜로 보여 줌(Raycast, GitHub).
- 문제 해결은 본문 맨 아래(Troubleshooting 또는 FAQ). 하단에서 행동 버튼을 다시 반복하는 곳은 없었음.

### 가져올 패턴 5개
1. **상단 한 덩어리**: 이름, 한 줄 설명, 만든 곳, 주 버튼 한 개를 한눈에 묶음. (Raycast, VS Code)
2. **사용법을 복사 가능한 짧은 블록으로, 상단 가까이에**: 비개발자용이므로 "이 문구를 Claude에 입력"처럼 번호 단계 + 복사 버튼. (VS Code의 Installation 박스, GitHub의 사용 블록)
3. **"안전한가" 구역을 따로 만들고 사실만 적음**: 만든 곳, 파일 내용 전체 공개(소스 보기), 외부로 보내는 것 없음, 필요한 권한. 권장 권한을 명시하는 GitHub 방식이 참고. (GitHub, Raycast의 공개 소스 링크)
4. **날짜 있는 변경 기록**: 가짜 수치 대신 쓸 수 있는 진짜 신뢰 요소. (Raycast 버전 기록, GitHub 릴리스 노트)
5. **결과물 영역 + 문제 해결 FAQ를 본문 아래에 둠**: 실제 결과 화면(캡션 포함)을 사용법 다음에 놓고, FAQ·문제 해결은 맨 아래에. 사이드바는 "정보 요약(버전, 조건, 소스)" 용도로만. (Raycast, VS Code, GitHub)

### 피할 패턴 5개
1. **설치 수, 별점·평점, 리뷰 수 표시**(VS Code, Notion, Raycast). 실제 데이터가 없는 SkillBite가 쓰면 가짜 수치가 됩니다.
2. **"인증됨/Verified/Top creator" 배지 모양**. 확인해 줄 주체가 없으면 거짓 표시입니다. 대신 사실(누가 만들었나)을 글로 적습니다.
3. **탭 4개 이상, 긴 변경 기록이 본문을 채우는 구성**(VS Code, GitHub). 스킬은 파일 하나라서 과합니다. 정보는 한 화면에 이어서 읽히게 합니다.
4. **캡션 없는 스크린샷 모음**(Raycast에서 캡션이 안 보임). 무엇을 보여 주는지 알 수 없는 이미지는 안심 효과가 없습니다.
5. **비어 있거나 잘못된 정보 칸**(Notion의 설명 없음, 이상한 갱신일, "함께 보는 항목"만 늘어놓기). 값이 없으면 칸을 두지 않고, 확인 안 된 값은 `[확인 필요]`로 둡니다.

### 확인 못 한 것(후속 조사 후보)
본문 폭(px), 사이드바 실제 너비, 모바일에서의 버튼 위치, 하단 행동 반복의 효과, npm·Zapier·Gumroad 화면은 직접 보지 못했습니다. 브라우저로 직접 보는 조사가 필요합니다.

### SkillBite 상세에 적용할 제안 3가지
첫째, 상단에 이름·한 줄 설명·만든 곳·"스킬 파일 받기" 버튼 한 개를 묶고, 바로 아래에 번호 단계로 된 "쓰는 방법"(복사 버튼 포함)을 둡니다. 설치 경로나 재시작 여부처럼 확인 안 된 값은 `[확인 필요]`로 남깁니다. 둘째, "안전한가요?" 구역을 만들어 파일에 들어 있는 것(평문 지시문뿐), 외부로 보내는 것 없음, 만든 곳, 파일 전체 보기 링크를 사실로만 적고, 별점·다운로드 수·인증 배지는 쓰지 않습니다. 셋째, 쓰는 방법 다음에 캡션 달린 실제 Claude 대화 결과 화면을 넣고, 맨 아래에 문제 해결 FAQ와 날짜 있는 변경 기록을 둡니다. 사이드바는 버전·갱신일·필요 조건을 요약하는 용도로만 쓰고, 좁은 화면에서는 본문 위나 아래로 접어 한 줄로 읽히게 합니다.
