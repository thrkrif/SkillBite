# 홈 화면 레퍼런스 조사: 국내 서비스와 'AI 템플릿 티'

조사일: 2026-10-25. WebFetch/WebSearch로 확인한 내용만 적었습니다. 확인하지 못한 것은 '미확인'으로 표시했습니다. 사이트 문구는 요약만 담았습니다.
주의: WebFetch는 요약 모델을 거치므로 시각 요소(색, 간격, 모서리)는 확인하지 못했습니다. 아래는 구조·정보·카피 위주입니다.

## 1. 국내 서비스

### 1-1. 미리캔버스 (miricanvas.com/ko)
- 히어로: 큰 한 줄 헤드라인과 짧은 설명, 버튼 2개("바로 시작하기", "템플릿 보러가기"). 위쪽에 템플릿 썸네일이 가로로 흐르는 띠가 있습니다.
- 목록 단위: 세로형 썸네일 카드. 이미지와 짧은 제목만 있습니다. 제목은 "색 + 스타일 + 용도" 구조입니다(예: 베이지 미니멀 발표자료 형태). 유형별 묶음 카드는 목업, 제목, 한 줄 설명, 버튼으로 구성됩니다.
- 정보 밀도: 낮음. 카드 하나에 정보가 거의 없고 이미지가 말합니다.
- 신뢰 요소: 이용자 수, 템플릿 수, 다운로드 수 같은 큰 수치. 보안 인증 마크. 푸터에 사업자 정보와 고객센터.
- 카피 톤: 존댓말, 권유형("~해보세요"). 진입 장벽이 낮다는 말을 반복하고, "막막하셨나요?" 같은 공감 질문으로 시작합니다.
- AI 티 안 나는 이유(해석): 카드가 글이 아니라 실제 결과물 썸네일입니다. 제목이 구체적인 설명문입니다.
- SkillBite 주의: 미리캔버스의 수치는 실제 운영 규모라 가능한 것입니다. 우리는 가짜 수치가 없으므로 따라 하면 안 됩니다.

### 1-2. 노션 템플릿 갤러리 (notion.com/ko/templates)
- 히어로: 템플릿 개수를 앞세운 헤드라인, 커뮤니티가 만들었다는 부제, 위쪽 탭(템플릿/에이전트/AI 스킬 등).
- 목록 단위: 종류별로 카드 모양이 다릅니다. 템플릿 카드는 미리보기 이미지, 제작자 아바타와 이름, 가격(무료 표시)입니다. 모음 카드는 작은 분류 태그, 굵은 제목, 한 줄 설명, "둘러보기" 링크입니다. 분류 카드는 이름과 개수입니다.
- 정보 밀도: 중간. 분류마다 개수가 붙어 규모를 보여 줍니다.
- 신뢰 요소: 분류별 템플릿 수, 제작자 수 등 집계 수치, 제작자 프로필.
- 카피 톤: 해요체, 짧은 제목, 행동 동사.
- 참고: 'AI 스킬' 분류가 이미 있습니다. 가장 가까운 경쟁·참고 사례입니다.
- AI 티 안 나는 이유(해석): 카드 모양을 한 가지로 통일하지 않고 목적별로 다르게 둡니다. 실제 제작자와 실제 수치가 있습니다.

### 1-3. 숨고 (soomgo.com)
- 히어로: 상황형 큰 문구 한 줄, 그 아래 "어떤 서비스가 필요하세요?" 질문형 검색, 주요 버튼 하나, 자동 넘김 배너.
- 목록 단위: 아이콘+이름 카드 그리드. 묶음 제목이 상황형입니다("이사 준비", "집 점검" 같은 상황 이름).
- 신뢰 요소: 안전거래·보증 관련 메뉴가 여러 곳에 있고, 푸터에 신고번호·사업자등록번호·고객센터·전국 지역 목록이 상세합니다. 고수 수·거래 건수 같은 집계 수치는 확인되지 않았습니다.
- 카피 톤: 친근한 존댓말, 막막한 상황을 안심시키는 말투.
- 배울 점: 카테고리 이름을 '업종'이 아니라 '상황'으로 붙입니다.
- 주의: 같은 항목이 위 그리드와 아래 카드에 두 번 나옵니다. 중복은 따라 하지 않는 편이 좋습니다.

### 1-4. 당근 (daangn.com)
- 히어로: 큰 배너 없이 짧은 제목과 앱 안내. 사용자 동네 기반 탐색이 앞에 있습니다.
- 목록 단위: 번호 붙은 세로 목록(제목, 분류 태그, 댓글·좋아요 수, 작은 썸네일). 맛집은 가로 카드 묶음, 생활서비스는 아이콘 그리드. 한 화면에 목록 모양이 여러 종류입니다.
- 신뢰 요소: 이웃 리뷰 건수, 푸터의 사업자·통신판매업·약관 링크.
- 카피 톤: 구어체, 이웃 간 대화 같음.
- 배울 점: 정보 밀도가 높아도 목록이 '한 줄 + 태그 + 작은 숫자'로 정리돼 있으면 답답하지 않습니다.

### 1-5. 클래스101 (class101.net)
- 확인한 것: 페이지 제목 문구 한 줄, 구독/개별 구매 구분, 26개 분야 카테고리 나열(AI 스킬업 포함). 
- 카드 정보(가격·평점), 히어로 전체 문구, 신뢰 요소: 미확인. 페이지 내용이 메뉴 위주로만 받아졌습니다.

### 1-6. 뤼튼 (wrtn.ai)
- 접속 실패(HTTP 402). 미확인.

### 1-7. 토스 (toss.im)
- 홈 본문을 받지 못했습니다(상단 메뉴만 확인). 히어로·목록·신뢰 요소: 미확인.
- 대신 토스 UX Writing 기사(toss.im/tossfeed/article/uxwriter-interview)에서 확인한 것: 서비스가 40개 넘어도 말투를 하나로 맞추는 UX 라이터 역할이 있고, 오류 때 불쾌함을 줄이는 것까지 맡습니다. 해요체·문장 길이에 대한 공식 규칙은 이번 조사에서 미확인입니다.

### 국내 서비스 공통 관찰
1. 목록 카드 모양이 한 가지가 아니고, 내용 종류에 맞게 다릅니다(썸네일형, 아이콘형, 텍스트 행).
2. 카드 제목이 구체적인 설명문이거나 상황 이름입니다. 추상어("스마트", "혁신")가 거의 없습니다.
3. 신뢰는 (a) 실제 수치, (b) 사업자 정보·약관을 푸터에 정직하게 노출, (c) 제작자 프로필로 만듭니다. 수치가 없는 서비스(숨고)는 안전·정책 안내와 법적 정보로 대신합니다.
4. 말투는 모두 존댓말(해요체)이고 짧습니다.
5. 히어로는 대개 '한 줄 약속 + 버튼 1~2개'입니다. 장식 그라데이션은 요약에서 확인되지 않았습니다(시각은 미확인).

## 2. 'AI 템플릿 티' 연구

주의: 아래 근거는 모두 실무자 글·도구 문서입니다. 통계 연구가 아니라 의견과 관찰입니다. 한국어 토론 글은 이번 검색에서 찾지 못했습니다(미확인).

| 패턴 | 근거 | 대안 |
| --- | --- | --- |
| 보라-파랑 그라데이션, 그라데이션 글자 | Fountain Institute 글, Impeccable 목록, DEV 글 | 브랜드 단색 하나(우리는 노랑)로 강조 |
| 이모지를 아이콘·내비로 사용 | Fountain Institute, DEV 글 | 일관된 아이콘 세트 또는 아이콘 없음 |
| 똑같은 카드 격자, 카드 속 카드 | Fountain Institute(cards on cards), Impeccable(identical card grids) | 간격과 구분선으로 묶기, 카드는 꼭 필요한 곳만 |
| 과한 둥근 모서리 | Impeccable(extreme radii), 정리 글(12~16px 권장) | 카드 크기에 맞춘 작은 반경 |
| 카드 옆 색 띠, 모든 곳의 상태 점 | Fountain Institute, Impeccable | 강조색은 선택 상태에만 사용 |
| 오로라 빛 번짐, 유리 효과, 떠다니는 입자 | Fountain Institute, DEV 글 | 단색 배경 |
| 제목 위 작은 배지·라벨, 제목 위 아이콘 칸 | Impeccable | 제목에 합치거나 삭제 |
| 중앙 큰 제목 + 짧은 문단 + 버튼 + 카드 3~4장 + 로고 줄 + 추천사 + 끝 버튼이라는 정해진 순서 | DEV 글("Why AI Websites All Look the Same" 계열) | 실제 내용에서 구조를 도출 |
| 막연한 마케팅 문구, "A가 아니라 B" 대조 문장, 줄표 남발 | Impeccable(Copy) | 사용자가 할 수 있는 일을 직접 말하기 |
| 문장 끝 외톨이 단어 | Impeccable | text-wrap: balance / pretty |

보완: 한 글은 AI 사이트가 대체로 보기 좋고 작동도 하지만 '기억에 남지 않는다'는 점이 문제라고 합니다. 또 디자인 시스템(토큰)으로 일관성을 잡으면 의도된 디자인처럼 보인다는 의견도 있습니다. 우리에게는 DESIGN.md가 그 역할을 합니다.

## 3. 한국어 타이포그래피·카피 팁

확인한 것(daleseo.com/css-text-wrap 등 검색 요약):
- 한국어는 글자 사이 어디서든 줄이 끊길 수 있어서 `word-break: keep-all`로 어절 단위 줄바꿈을 먼저 맞춥니다.
- 제목에는 `word-break: keep-all`과 `text-wrap: balance`를 함께 쓸 수 있습니다. 마지막 줄에 단어 하나만 남는 것을 줄입니다.
- `text-wrap: balance`의 브라우저별 지원 범위는 이번에 미확인입니다. 적용 전 MDN/Can I use 확인이 필요합니다.
- keep-all은 긴 어절이 좁은 화면에서 넘칠 수 있으므로 `overflow-wrap` 보조가 필요한지 직접 확인하세요(이 부분은 제 추정이며 미검증).

카피(국내 서비스 관찰에서 정리, 해석 포함):
- 해요체/합니다체 중 하나로 통일합니다. 우리 지침은 존댓말이므로 해요체 중심이 자연스럽습니다.
- 제목은 한 줄 약속, 설명은 한두 문장. 추상어보다 "무엇을 해 주는지"를 씁니다.
- 카드 제목은 미리캔버스처럼 구체적인 설명문으로 씁니다.
- 영어 전문용어(SKILL.md, 프롬프트 등)는 첫 등장에 쉬운 말로 풀어 줍니다.
- 토스처럼 오류·빈 상태 문구까지 같은 말투로 맞춥니다.

## 4. 종합

### 가져올 패턴 5개
1. 목록 카드 제목을 "무엇을 해 주는지"가 보이는 구체적 설명문으로 쓰기(미리캔버스).
2. 분류 이름을 업종이 아니라 상황·업무로 붙이기(숨고). 예: "블로그 글 쓰기" 같은 업무 이름.
3. 신뢰는 가짜 수치 대신 정직한 정보로 만들기: 만든 사람, 최종 수정일, 파일 크기/형식, 사용 전 확인 사항, 푸터의 문의·정책(숨고, 당근 푸터, 노션 제작자 프로필). 실제로 확인되는 값만 씁니다.
4. 정보 밀도는 '제목 한 줄 + 한 줄 설명 + 작은 태그'로 정리하고, 카드 모양을 내용에 맞게 다르게 쓰기(당근, 노션). 스킬이 1개일 때는 큰 카드 1장+안내 행으로 비어 보이지 않게 하고, 늘어나면 같은 구조로 확장.
5. 히어로는 '한 줄 약속 + 버튼 1~2개 + 필요하면 검색'으로 끝내고, 제목에 `word-break: keep-all` + `text-wrap: balance` 적용(미리캔버스, 숨고, 한국어 줄바꿈 글).

### 피할 패턴 5개
1. 보라-파랑 그라데이션, 그라데이션 글자, 빛 번짐.
2. 이모지를 아이콘으로 쓰기, 제목 위 작은 배지·아이콘 칸.
3. 똑같은 카드 3열 반복과 카드 속 카드, 색 띠·상태 점 남발.
4. 과한 둥근 모서리와 유리 효과(반경은 DESIGN.md 값 안에서만).
5. 가짜 수치·후기·고객 로고 줄·추천사, 막연한 마케팅 문구와 "A가 아니라 B" 식 문장. (미리캔버스·노션의 큰 수치는 실제 규모라 가능한 것이며, 우리는 따라 할 수 없습니다.)
