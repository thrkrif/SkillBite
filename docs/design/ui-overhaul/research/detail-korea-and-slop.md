# 상세 페이지 레퍼런스 조사: 국내 서비스와 'AI 템플릿 티'

조사일: 2026-10-31. WebFetch/WebSearch로 확인한 내용만 적었습니다. 확인하지 못한 것은 '미확인'으로 표시했습니다.

## 한계 (먼저 읽어 주세요)
- WebFetch는 요약 모델을 거치므로 시각 요소(색, 간격, 모서리, 버튼 크기)는 확인하지 못했습니다. 구조·문구·정보 위주입니다.
- 이번에 **개별 상세 페이지 본문을 받은 곳은 노션 템플릿 1곳뿐**입니다. 미리캔버스는 목록만, 한컴은 다운로드 센터 목록만, 인프런·당근은 메뉴 수준만 받아졌습니다. 상세 페이지 구성에 대한 결론은 그만큼 약합니다.
- 'AI 티' 근거는 실무자 글입니다. 통계 연구가 아니라 관찰과 의견입니다. 한국어 글은 찾지 못했습니다(미확인).
- 검색 결과에 체크 아이콘 목록, FAQ 아코디언을 직접 다룬 글은 없었습니다. 그 부분은 아래에서 '근거 없음'으로 표시하고 제 해석임을 밝혔습니다.

## 1. 국내 서비스

### 1-1. 노션 템플릿 상세 (notion.com/ko/templates/ai-prompt-library)
- 확인: 제작자 프로필(이름, 만든 템플릿 수) 아래에 "템플릿 보기" 버튼. 이메일 문의, 외부 링크 등 제작자 연락 수단이 있습니다.
- 확인: 평점 4.95(평가 75개)와 이용자 후기 4건이 신뢰 요소입니다. 별도의 안심 문구는 없습니다.
- 확인: 사용(복제) 방법 안내 없음, FAQ 없음, 설명란 비어 있음. 최종 수정일이 "56년 전"으로 잘못 표시됨(날짜 오류 예).
- 해석: 상세 페이지가 의외로 간단합니다. 안내보다 '누가 만들었고 다른 사람은 어땠는지'가 중심입니다. 날짜 오류는 반대로 '최종 수정일을 정확히 쓰면 신뢰가 된다'는 근거로 읽힙니다.
- 노션 AI 스킬 카테고리(목록): 설명 문구가 "스킬을 워크스페이스에 복사해 출력 형식을 표준화하고 반복 작업에 드는 시간을 줄이세요." 한 문장으로 쓰는 일과 결과를 말합니다. 카드마다 제작자 사진과 이름이 있습니다. 주 버튼은 "Notion 무료로 사용하기"(상단). 카테고리 아래 FAQ는 있으나 스킬과 무관한 내용(프로젝트 관리 템플릿)이었습니다.

### 1-2. 한컴 다운로드 센터 (hancom.com/support/downloadCenter/download)
- 확인: 제품별 카드마다 버튼이 카드 안에 있습니다("다운로드", "설치파일 다운로드"). 일반용·기업용처럼 대상에 따라 버튼이 나뉩니다.
- 확인: 설치 방법 단계 안내는 없고, 운영체제·메모리 같은 시스템 요구사항만 표시합니다.
- 확인: 안심 문구는 "패치는 보안 강화와 문제 해결 목적"이라는 이유 설명 형태입니다. 하단에 사업자 정보, 인증 마크, 전화번호·이메일(평일 9~18시)이 있습니다.
- 확인: 로그인 후 받아야 하는 항목은 카드에 그 사실이 드러납니다. FAQ 없음.
- 해석: 안심을 '괜찮습니다'라고 외치지 않고 이유와 연락처로 줍니다. 필요한 조건(사양)은 숨기지 않고 바로 적습니다.

### 1-3. 미리캔버스 템플릿 (miricanvas.com/templates)
- 확인: 목록은 스타일별·직업별 탐색, 주제별 섹션, 카드(썸네일+제목), 섹션 끝 "더 보기" 링크. 카드 자체가 링크입니다.
- 미확인: 개별 템플릿 상세 페이지, 사용 안내, 안심 문구, FAQ. (영문 버전이 받아져 한국어 카피는 확인 못 함. 홈 조사 문서의 관찰을 참고하세요.)

### 1-4. 토스 UX 라이팅 기사 (toss.im/tossfeed/article/uxwriter-interview)
- 상세 페이지가 아니라 문구 원칙 자료입니다. 확인한 것:
  - 버튼이 하나일 때 "~하기" 형태, 화면을 넘길 때 "확인"/"다음", 버튼이 둘일 때 취소 대신 "닫기"/"다음에".
  - 기능 없는 단어를 걷어내는 간결함, 여러 사람이 써도 한 서비스처럼 느끼게 하는 통일된 말투.
  - 클릭률이 높아도 가치를 부풀리는 자극적인 문구는 지양.
  - 안내·안심 문구의 별도 원칙은 이 기사에 없음(미확인). 사실 전달을 공감 문구로 바꿔 지표가 좋아진 사례가 하나 있음.

### 1-5. 인프런 / 당근 (상세 미확인)
- 인프런: 메뉴와 "AI 교육 90% 환급" 배너만 확인. 강의 상세 구성, 환불 문구, FAQ 미확인. 강의 상세 URL은 404였습니다.
- 당근: 상단 "앱 다운로드", 푸터 "당근 앱 다운로드" 두 곳에 같은 문구. 설치 절차, 안심 문구, FAQ 미확인(푸터 "고객센터" 링크만).
- 클래스101, 숨고 등은 홈 조사 문서 참고. 상세는 이번에 미확인.

### 국내 서비스 공통 관찰 (확인된 범위 안에서)
1. 버튼 문구가 짧은 동사형입니다("다운로드", "템플릿 보기", "앱 다운로드").
2. 버튼은 상품 정보(제작자 또는 제품 카드) 바로 옆·아래에 있고, 같은 문구를 위·아래 두 곳에 두는 곳도 있습니다(당근).
3. 설치 단계 안내를 상세 페이지에 길게 쓰지 않는 곳이 많습니다(한컴, 노션). 필요한 조건(사양)만 적습니다.
4. 안심은 이유 설명, 연락처, 사업자 정보, 제작자 프로필, 실제 평점으로 만듭니다. '안심하세요' 박스는 이번에 본 곳에서 확인되지 않았습니다.
5. FAQ는 모든 곳에서 상품 상세 안에 없거나 상품과 무관했습니다. 단, 이는 확인한 5곳에 한한 이야기입니다.

## 3. 종합

### 가져올 패턴 5개
1. 버튼은 짧은 동사형으로 하나(예: "내려받기"), 스킬 이름과 제작자 바로 옆에 둔다(노션, 한컴, 토스 "~하기").
2. 안심은 사실과 이유로: 제작자, 최종 수정일, 파일 형식·크기, 사용하기 전에 알아야 할 것, 문의 방법(한컴의 이유 설명+연락처, 노션 제작자 프로필). 확인 안 된 값은 `[확인 필요]`.
3. 필요한 조건(사양)을 숨기지 않고 한 줄로 적는다(한컴의 시스템 요구사항 방식). 우리라면 사용 가능한 Claude 환경 등.
4. 설명은 "무엇을 해 주고 어떤 결과가 나오는지" 한 문장(노션 카테고리 설명). 부제로 제목을 되풀이하지 않는다.
5. 말투 통일과 간결함: 불필요한 단어를 걷어내고 오류·빈 상태까지 같은 말투로(토스).

### 피할 패턴 5개
1. 아이콘+굵은 제목+한 문장으로 이루어진 같은 카드 반복(안심 3칸, 기능 3칸 포함).
2. 번호 단계의 원형 배지, 작은 번호 섹션 라벨.
3. 색 칸 안에 아이콘을 넣은 '안심 박스'와 체크 아이콘 장점 목록(근거 약함, 해석).
4. 과한 FAQ 아코디언, 제목 위 배지, 같은 문구의 반복.
5. 가짜 후기·수치·별점(노션의 평점은 실제 이용자가 있어서 가능). 보라 그라데이션, 빛 번짐, 유리 효과, 줄표 남발.

### SkillBite 상세에 적용할 제안 3가지
1. **정보 먼저, 장식은 없음**: 맨 위에 제목, 한 문장 설명, "내려받기" 버튼 하나, 메타 줄(만든 사람 · 최종 수정일 · 파일 형식). 안심 박스를 따로 만들지 않고 메타와 본문 문장이 안심 역할을 하게 합니다.
2. **사용법은 번호 순서 목록으로, 카드와 아이콘 없이**: `ol` 평문 3~4줄(내려받기, 놓을 위치 `[확인 필요]`, 이름으로 부르기). 설치 경로·재시작 여부는 확인 전까지 `[확인 필요]`를 그대로 둡니다. 스킬 파일 내용 미리보기는 제 코드 블록 하나로 보여 줍니다.
3. **FAQ는 줄이고 펼치지 않기**: 정말 필요한 질문 2~3개를 본문에 그대로 펼쳐서 쓰고, 확인된 답이 없으면 넣지 않습니다. 같은 내용을 위·아래에 두 번 쓰지 않습니다.
