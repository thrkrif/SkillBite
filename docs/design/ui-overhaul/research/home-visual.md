# 목록 화면(홈) 시각 조사: 실제 화면 관찰

조사일: 2026-10-25. 브라우저 너비 1440px(화면 높이 약 693px)에서 첫 화면과 1~2번 스크롤한 화면을 직접 봤습니다. 모든 수치는 눈대중이라 "대략"입니다. 못 본 것은 "미확인"으로 적었습니다. 사이트 문구는 옮기지 않고 요약만 했습니다. 스크린샷 파일은 저장소에 넣지 않았습니다.

## 사이트별 관찰

### 1. Raycast Store (어두운 테마)
- 색: 배경 거의 검정(대략 #0A0A0A), 제목은 흰색, 설명은 회색(대략 #8A8A8A). 위쪽에 빨강 계열 사선 그림이 크게 깔림.
- 크기: 첫 화면 큰 제목은 대략 72px, 아래 설명은 대략 18px로 약 4배. 섹션 제목(Explore)은 대략 40px, 부제는 대략 20px, 카드 제목은 대략 20px, 카드 설명은 대략 15px.
- 폭과 여백: 내용 폭 대략 1140px(좌우 여백 약 150px). 상단 메뉴는 둥근 캡슐 모양으로 떠 있고 폭이 약간 더 넓음.
- 간격: 섹션 제목 위아래 여백이 넉넉함(대략 120px 이상). 첫 화면은 아이콘 묶음, 큰 제목, 검색창 순으로 세로로 길게 쌓임.
- 카드: 3열, 카드 폭 대략 360px, 칸 사이 대략 30px. 테두리는 아주 옅고(배경보다 살짝 밝은 정도), 모서리는 대략 8px로 약하게 둥글고, 그림자는 없음. 카드 안은 가운데 정렬: 큰 앱 아이콘(둥근 상자 안), 이름, 두 줄 설명, 만든 사람 순.
- 밀도: 낮음. 한 화면에 카드가 한 줄(3개)만 보임.
- 이미지: 앱 아이콘이 주인공. 아이콘에 은은한 광택 상자를 씌움. 배경의 사선 그림은 장식.
- 버튼: 오른쪽 위 '다운로드'만 밝은 회백색 채움 버튼(모서리 대략 8px). 나머지는 글자만.
- AI 템플릿 티: 큼직한 사선 그라데이션 배경, 가운데 정렬 큰 제목, 흐릿한 아이콘 묶음은 요즘 흔한 연출이라 템플릿 느낌이 남. 반면 카드 목록 자체는 단정하고 절제돼 운영 서비스 같음.

### 2. Zapier 앱 디렉터리 (밝은 테마)
- 색: 배경 따뜻한 아이보리(대략 #FFFDF9), 글자 진한 갈색 계열 검정(대략 #201515), 포인트는 주황 버튼(대략 #FF4F00). 링크·선택 항목은 보라 계열.
- 크기: 첫 화면 제목 대략 56px, 부제 대략 18px로 약 3배. 목록 섹션 제목 대략 28px, 앱 이름 대략 17px 굵게, 설명 대략 15px 회색.
- 폭과 여백: 내용 폭 대략 1280px(좌우 여백 약 80px). 왼쪽에 분류 사이드바(대략 300px), 오른쪽에 목록.
- 간격: 위쪽 소개 영역과 목록 사이는 보통(대략 60~80px). 목록 줄 사이 대략 30px.
- 목록 단위: 카드가 아니라 '테두리 없는 줄'. 작은 아이콘(대략 40px, 옅은 테두리 상자) + 굵은 이름 + 두 줄 설명(끝을 말줄임). 2열 배치. 구분선도 그림자도 없음.
- 밀도: 높음. 한 화면에 앱 10개 이상. 왼쪽 필터와 정렬 메뉴가 항상 보임. 앱이 9,000개 이상이라 이런 구조가 필요해 보임.
- 이미지: 아이콘만 사용. 사진 없음.
- 버튼: 오른쪽 위 '가입' 하나만 주황 채움 알약형. 나머지는 글자 링크.
- AI 템플릿 티: 거의 없음. 정렬 메뉴, 분류, 개수 표시("전체 중 1-22") 같은 운영 장치가 있어 실제 서비스처럼 보임. 위쪽 소개 영역(점 무늬 배경, 알약형 태그 줄)은 조금 마케팅 느낌.

### 3. GitHub Marketplace (어두운 테마, 로그인 상태)
- 색: 배경 짙은 남회색(대략 #0D1117), 카드 배경은 조금 밝음(대략 #151B23), 글자는 흰색·회색. 포인트는 파랑(인증 표시).
- 크기: 위 배너 제목 대략 32px 굵게, 부제 대략 18px(약 1.8배). 카드 이름 대략 16px, 카드 설명 대략 13px.
- 폭과 여백: 왼쪽 사이드바(대략 280px) 고정 + 오른쪽 본문. 본문 좌우 여백 대략 25px로 좁고 꽉 참.
- 카드: 3열, 카드 폭 대략 355px, 칸 사이 대략 15px. 옅은 회색 테두리, 모서리 대략 6px, 그림자 없음. 오른쪽 위에 작은 '앱' 알약 라벨, 가운데 아이콘, 이름, 한 줄~두 줄 설명 순. 인증된 항목은 이름 옆 작은 파란 표시.
- 밀도: 중간~높음. 첫 화면에 카드 두 줄(6개)이 보임.
- 이미지: 아이콘만. 배너 오른쪽에 추상 도형 그림은 있으나 작음.
- 버튼: 화면에 눈에 띄는 큰 버튼 없음. 검색창이 중심.
- AI 템플릿 티: 거의 없음. 사이드바, 종류 라벨, 인증 표시가 있어 '실제 목록 서비스'의 정석처럼 보임.

### 4. Linear 홈 (어두운 테마, 일부만 봄)
- 색: 배경 거의 검정(대략 #08090A), 메뉴 글자는 회색, '가입' 버튼만 밝은 회백색 알약형(대략 #E6E6E6).
- 폭과 여백: 상단 메뉴 좌우 여백 대략 80px, 얇은 구분선 한 줄. 큰 앱 화면 그림은 폭 대략 1320px로 넓게 펼침. 모서리 대략 16px로 둥글고 은은한 안쪽 테두리.
- 그 외 제목 크기, 첫 화면 구성은 로딩이 끝나지 않아 미확인.
- 보인 것: 고객 로고 줄은 흰색 한 가지 색으로 통일해 7개를 한 줄로 나열(대략 28px 높이). 아래에 영문 대문자 작은 글씨(고정폭 글꼴 느낌)로 설명 한 줄.
- 이미지: 실제 제품 화면을 크게 보여줌. 가짜 일러스트가 아님.
- AI 템플릿 티: 고객 로고 한 줄과 제품 화면 캡처는 흔한 구성이지만, 실제 제품 화면이라 설득력이 있음.

### 5. Stripe 홈 (밝은 테마)
- 색: 배경 흰색~연한 회청색(대략 #F6F9FC), 제목은 아주 짙은 남색(대략 #0A2540), 두 번째 문장은 회청색(대략 #6B7C93)으로 같은 제목 안에서 색을 바꿈. 버튼은 보라(대략 #635BFF). 오른쪽에 주황·분홍·보라 리본 그림이 크게 있음.
- 크기: 제목 대략 44px 가볍게(가는 굵기), 두 줄째까지 같은 크기로 이어짐. 본문 대략 16px. 제목이 본문의 약 2.7배.
- 폭과 여백: 내용 왼쪽이 대략 208px부터 시작. 바깥에 아주 옅은 세로선 두 줄이 내용 폭(대략 1265px)을 표시.
- 카드: 두 칸, 흰 배경, 옅은 회색 테두리, 모서리 대략 6px, 그림자는 거의 없음. 카드 위에 제목 한 줄, 아래에 실제 제품 화면 목업이 큼직하게 들어감. 오른쪽 위에 확대 아이콘 버튼.
- 버튼: 채움 보라 버튼 + 테두리만 있는 보조 버튼 쌍. 모서리 대략 4px로 각진 편. 첫 화면 오른쪽 위에도 같은 쌍.
- 쿠키 배너: 오른쪽 아래 작은 카드, '모두 수락'과 '모두 거부' 두 버튼이 같은 모양. 거부를 눌렀음.
- 밀도: 낮음~중간. 첫 화면은 제목, 버튼 둘, 고객 로고 줄이 전부.
- AI 템플릿 티: 큰 그라데이션 리본은 화려하지만 글자와 겹치지 않게 오른쪽에 둬서 읽기는 쉬움. 카드 안 제품 화면이 구체적이라 템플릿 같지 않음. 이 사이트는 이미지가 신뢰를 만드는 사례.

### 6. Vercel 템플릿 갤러리 (어두운 테마, 요청 목록 밖이지만 봄)
- 색: 배경 순수 검정(#000 가까이), 카드 아래 글 영역은 아주 짙은 회색(대략 #0A0A0A), 글자 흰색/회색.
- 크기: 페이지 제목 대략 48px, 아래 설명 대략 16px(약 3배). 카드 이름 대략 18px, 설명 대략 14px.
- 폭과 여백: 좌우 여백 대략 24px로 좁고 화면 가득 사용.
- 카드: 3열, 칸 사이 대략 24px. 옅은 회색 테두리, 모서리는 거의 각짐(대략 2~4px), 그림자 없음. 위쪽 큰 썸네일(대략 235px 높이) + 아래 이름과 두 줄 설명. 썸네일이 글자뿐인 경우도 있어서 이미지 품질이 들쭉날쭉함.
- 버튼: '문의', '대시보드' 두 개가 테두리만 있는 작은 버튼. 오른쪽 위에 검색창과 '필터' 버튼이 나란히 있음.
- 밀도: 중간. 첫 화면에 카드 한 줄과 그 위 제목·검색.
- AI 템플릿 티: 거의 없음. 검색과 필터가 제목과 같은 줄에 있는 배치가 실제 갤러리 느낌.

## 종합 비교(눈으로 본 범위)
- 어두운 테마가 4곳(Raycast, GitHub, Linear, Vercel), 밝은 테마가 2곳(Zapier, Stripe). 카드 모서리는 대부분 대략 4~8px로 작고, 그림자는 모든 카드 목록에서 쓰지 않았음. 카드는 옅은 테두리로 구분.
- 제목 대 본문 비율은 대략 2.7~4배. 목록 영역 안의 제목은 28~48px로 줄여 쓰고, 큰 글씨는 첫 화면 소개에만 씀.
- 목록 사이트(Zapier, GitHub, Vercel)는 소개 영역이 짧고 검색·분류·정렬이 바로 보임. 소개가 긴 사이트(Raycast, Stripe, Linear)는 홍보 사이트에 가까움.
- 버튼은 화면당 채움 버튼 1개가 기본. 나머지는 테두리 또는 글자 링크.

## 가져올 시각 규칙 8개
1. 소개 영역은 짧게(제목 1개 + 한 줄 설명 + 검색), 그 아래 바로 스킬 목록이 보이게 합니다. 첫 화면 안에 카드가 최소 1줄은 보이게 합니다. (Zapier, GitHub, Vercel처럼)
2. 첫 화면 제목은 본문 글자의 약 3배(예: 본문 16px이면 제목 약 44~48px)로 하고 굵기는 너무 굵지 않게 합니다. 목록 구역 제목은 본문의 약 1.7배(대략 28px). 4배를 넘는 큰 제목은 쓰지 않습니다.
3. 카드는 그림자 대신 옅은 회색 테두리(대략 1px)와 작은 모서리(대략 8px 이하)로 구분합니다. 마우스를 올리면 테두리만 진해지게 합니다.
4. 카드 한 장은 정보 4가지만 담습니다: 아이콘(또는 이미지), 이름, 두 줄 이내 설명, 작은 라벨 1~2개(예: 업무 분류, '확인됨' 같은 표시). 모든 카드가 같은 순서·같은 높이를 가집니다.
5. 내용 폭은 대략 1140~1280px로 제한하고 좌우 여백은 큰 화면에서 대략 80~150px, 작은 화면에서 16~24px로 합니다. 카드는 3열(큰 화면) → 2열 → 1열로 줄입니다.
6. 색은 바탕 1색, 글자 2단계(진한 것/회색), 포인트 노랑 1색으로 제한합니다. 노랑은 채움 버튼과 선택 표시처럼 눌러야 할 곳에만 씁니다. 노랑 바탕 위 글자는 #242424로 두어 대비를 확보합니다. (Zapier처럼 따뜻한 밝은 바탕 + 포인트 1색이 가장 비슷한 사례)
7. 버튼은 화면당 채움 버튼 1종류(주 행동)와 테두리 버튼(보조)만 씁니다. 목록 카드 안에는 큰 버튼을 두지 않고 카드 전체를 누르게 합니다.
8. 스킬이 늘어날 때를 대비해 검색창, 분류 칩, 개수 표시("전체 N개")를 처음부터 자리 잡아 둡니다. 스킬이 1개일 때는 빈 칸을 채우려 가짜 카드를 만들지 않고, "새 스킬을 준비하고 있어요" 같은 짧은 안내 한 줄과 요청 안내를 둡니다.

## 피할 시각 패턴 5개
1. 큰 그라데이션·사선 배경 그림으로 첫 화면을 채우는 것. 눈은 가지만 목록을 밀어내고 템플릿처럼 보입니다. (Raycast, Stripe 첫 화면의 장식 부분)
2. 가운데 정렬 큰 제목 + 흐릿한 아이콘 묶음 + 알약형 태그 줄을 한 화면에 모두 넣는 구성. 요즘 흔한 AI 랜딩페이지 조합입니다.
3. 카드에 두꺼운 그림자, 큰 둥근 모서리(16px 이상), 색 테두리를 겹쳐 쓰는 것. 이번에 본 목록 사이트는 어디도 쓰지 않았습니다.
4. 실제 제품 화면이 없는데 가짜 그림이나 일러스트로 이미지 자리를 채우는 것. 썸네일이 글자만 있거나 품질이 들쭉날쭉하면(Vercel 일부 카드) 오히려 허술해 보입니다. 이미지가 없으면 정돈된 아이콘이나 글자 카드로 통일합니다.
5. 근거 없는 숫자·고객 로고·후기 줄(가짜 "수천 명이 사용"류)과 모든 문장에 강조 색을 쓰는 것. 믿음은 실제 스킬 화면, 사용 예, 확인된 정보로 만듭니다.
