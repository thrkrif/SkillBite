# 해외 레퍼런스 조사: 목록 화면(홈)

조사일: 2026-10-25. 방법: WebFetch로 각 페이지의 텍스트를 읽었습니다.

**한계(꼭 읽어 주세요)**: 이 도구는 페이지 글자만 뽑아 주기 때문에 글꼴, 색, 여백 수치, 실제 화면 모양은 대부분 확인하지 못했습니다. 해당 항목은 "미확인"으로 적었습니다. 시각 판단이 필요하면 브라우저로 직접 보는 후속 조사가 필요합니다. 문구는 요약만 적었습니다.

---

## 1. Raycast Store (raycast.com/store)

1. 히어로: 한 단어 제목("Store")과 한 문장 설명. 배경에 장식 그림이 있음. 상단에 로그인 버튼. 큰 히어로 문구나 큰 버튼 없이 곧바로 목록으로 들어감.
2. 목록 단위: 아이콘(목록 64px, 추천 128px), 이름, 한 줄 설명, 만든 사람 아바타와 이름, 설치 버튼, 사용량 숫자. 항목당 정보 약 5개로 중간 밀도. 일부에 "macOS 전용" 태그.
3. 적을 때/많을 때: 탭(전체, 최근 추가, 인기), 플랫폼 필터, 검색(⌘K), 번호 쪽수 이동(약 345쪽). 적을 때 처리는 미확인.
4. 타이포/여백: 미확인. 구조상 "제목 → 구역 제목(Explore, Featured, Extensions) → 소제목" 위계가 분명함.
5. 신뢰 요소: 설치 수, 만든 사람 이름·사진, 보안·약관 페이지 링크, 커뮤니티 링크. 단, 숫자는 실제 앱 사용 데이터라서 가능한 방식임. SkillBite는 같은 방식을 쓸 수 없음.
6. 티 안 나는 비결: 설명 문장이 짧고, 버튼이 앱을 바로 여는 실제 동작(딥링크)으로 연결됨. 장식보다 "기능하는 목록"이 화면의 대부분.

## 2. Notion 템플릿 갤러리 (notion.com/templates)

1. 히어로: 짧은 제목(숫자 포함)과 한 줄 설명. 버튼은 "무료로 시작", "데모 요청", 로그인. 그 아래에 둘러보기 탭과 검색.
2. 목록 단위: 미리보기 썸네일, 만든 사람 아바타와 이름, 가격 표시(대부분 Free). 제목은 추출 글에 안 보여 미확인.
3. 구역 순서: 소개, 추천 컨설턴트, 추천 템플릿, 추천 모음, 인기 분류(썸네일과 개수), 추천 제작자, "제작자 되기". 분류가 349개라 "전체 보기" 링크로 넘김.
4. 타이포/여백: 미확인. 큰 제목, 짧은 부제, 일정한 세로 간격이라는 구조만 확인.
5. 신뢰 요소: 숫자를 많이 씀(30,000+, 분류별 개수, 제작자 수 등). 자체 집계라 출처는 미확인. "Featured", "Top creator" 같은 라벨도 사용.
6. 참고: 숫자와 라벨을 많이 쓰는 방식은 규모가 있을 때만 통함. 항목이 1개인 SkillBite에는 맞지 않음.

## 3. Zapier 앱 디렉터리 (zapier.com/apps)

1. 히어로: 한 문장 설정("앱 N개를 연결해 코드 없이 자동화"). 히어로 버튼은 추출 글에 없음(미확인).
2. 목록 단위: 이름, 한두 문장 설명, 링크. 평점·가격·배지는 확인되지 않음. 즉 정보가 가장 단순함.
3. 구성: 추천 앱 1개, 분류 15개(앱 개수 표시), 인기 앱 22개, 전체 디렉터리 링크. 페이지 나누기 방식은 미확인.
4. 타이포/여백: 미확인.
5. 신뢰 요소: 앱 개수와 분류별 개수만. 후기·로고 없음.
6. 참고: "정보를 이름+설명 한두 줄로 줄이고, 분류 개수를 보여 주는" 방식이 단정함. 다만 SkillBite 분류는 지금 비어 있어서 개수 표시는 아직 쓸 수 없음.

## 4. Gumroad Discover (gumroad.com/discover)

읽어 온 내용이 페이지 제목뿐이었습니다(독립 제작자의 디지털 상품 장터). 히어로, 카드, 필터, 신뢰 요소, 타이포 모두 **미확인**. 근거로 쓰지 않습니다.

## 5. GitHub Marketplace (github.com/marketplace)

1. 히어로: 제목 한 줄과 부제 한 줄, 그 아래 검색창. 큰 그림 없음.
2. 목록 단위: 로고, 이름(링크), 한 줄 설명, 종류 라벨("App"). 정보 4개로 낮은 밀도.
3. 구성: 왼쪽 분류 사이드바(앱/액션), "추천/최근 추가" 전환, "제작자 만들기" 링크. 쪽수 이동은 보이지 않고 "More items"로 이어지는 것으로 보임(정확한 방식 미확인).
4. 타이포/여백: 미확인.
5. 신뢰 요소: 게시자 로고와 종류 라벨 정도. 인증 배지·평점은 추출 글에 없음(화면에는 있을 수 있어 미확인).
6. 티 안 나는 비결: 장식이 거의 없고 "검색 + 분류 + 균일한 카드"라는 도구 같은 구조.

## 6. Linear (linear.app)

1. 히어로: 짧은 제목(약 60자 영문), 한 줄 부제, 위에 작은 알약형 공지("New: ...")가 있음. 버튼은 "시작하기"(주), "영업 문의", 앱 열기, 다운로드.
2. 시각 요소: 추상 그림이 아니라 실제 제품 화면(이슈, 로드맵, 코드 리뷰). "Fig 0.1" 같은 작은 도면식 캡션으로 편집물 느낌.
3. 구성: 히어로, 가치 3개, 좌우 번갈아 나오는 기능 블록 4개, 날짜 달린 변경 기록, 고객 후기, 규모 숫자, 마무리 버튼, 푸터.
4. 타이포/여백: 큰 제목, 짧은 구역 제목, 작은 고정폭 글꼴 라벨이라는 구조 추정. 실제 값은 미확인.
5. 신뢰 요소: 이름·직함이 있는 후기, 고객 수 숫자, 보안·상태 페이지 링크. 숫자와 후기는 실제 고객이 있어서 가능함.
6. 티 안 나는 비결: 실제 데이터가 든 제품 화면, 짧은 단정문, 날짜 있는 변경 기록(계속 운영 중이라는 증거), 가격 카드나 이모지 없음.

## 7. Stripe (stripe.com)

1. 히어로: 짧은 제목(약 46자 영문), 길이가 더 긴 부제, 주 버튼과 보조 버튼 한 쌍.
2. 시각 요소: 고객 로고 띠, 작은 화면 조각이 든 벤토 카드, 큰 숫자 강조, 사례 카드. 모두 규모 있는 서비스용.
3. 신뢰 요소: 거래 규모, 가동률 등 큰 숫자, 실명 후기, 상태 페이지 링크, "은행이 아님" 같은 법적 고지.
4. 타이포/여백: 큰 제목, 문장형 소제목, 작은 보조 글이라는 위계. 넉넉한 여백으로 보이나 실제 값은 미확인.
5. 참고: 신뢰를 "실제 숫자와 실제 고객"으로 쌓는 사이트. SkillBite는 아직 이 재료가 없어서 그대로 따라 하면 가짜가 됨.

## 종합

### 가져올 패턴 5개
1. **히어로는 짧게(제목 한 줄 + 설명 한 문장)** 하고 목록을 화면 첫 장 안에 보이게 함. (Raycast, GitHub)
2. **카드 정보를 4~5개로 제한**: 아이콘, 이름, 한 줄 설명, 종류/태그, 받기 버튼. (Raycast, GitHub, Zapier)
3. **실제 제품 화면 이미지**를 시각 요소로 씀. 스킬을 쓸 때의 실제 Claude 대화 화면이 장식 그림보다 낫습니다. (Linear)
4. **날짜가 있는 "새 스킬/업데이트" 기록**으로 운영 중임을 보여 줌. 가짜 수치 대신 쓸 수 있는 진짜 신뢰 요소입니다. (Linear)
5. **받기 버튼이 실제로 동작하고, 만든 곳과 파일 내용을 투명하게 공개**함(무엇이 들어 있는지, 누가 만들었는지). 도구 같은 균일한 카드 구조로 정돈. (Raycast, GitHub)

### 피할 패턴 5개
1. **큰 숫자·"N+" 강조, 규모 자랑**(Notion, Stripe). SkillBite는 가짜 수치를 쓰지 않으므로 그대로 쓰면 거짓이 됩니다.
2. **고객 로고 띠와 후기 구역**(Linear, Stripe). 실제 고객이 없는 상태에서 쓰면 만든 티가 납니다.
3. **분류 수백 개와 쪽수 이동**(Raycast, Notion). 스킬 1개일 때 빈 필터와 빈 분류가 오히려 허전해 보입니다. 항목이 늘 때 추가합니다.
4. **벤토 카드, 그라데이션, 추상 일러스트 중심 히어로**. 템플릿 티의 주원인으로 보입니다(이 점은 Linear 설명에서 "쓰지 않아서 덜 템플릿 같다"고 읽은 추정이며, 직접 비교는 안 했습니다).
5. **가짜 평점, 가짜 다운로드 수, 가격 카드 모양의 장식**. 프로젝트 원칙과도 충돌합니다.

### 항목이 1개일 때(추정, 근거 약함)
조사한 곳은 모두 항목이 많아서 "1개일 때"의 직접 사례는 확인하지 못했습니다. 위 패턴을 바탕으로 한 제안이며, 카드 1개를 크게 보여 주는 "추천 카드" 형태(Raycast의 추천 카드가 참고)와 "곧 추가될 스킬 요청" 안내가 후보입니다. 확정이 아니라 후보입니다.
