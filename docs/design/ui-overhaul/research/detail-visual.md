# 상세 화면 시각 조사: 실제 화면 관찰

조사일: 2026-10-31. 브라우저 도구(Claude in Chrome)로 너비 1440px(화면 높이 약 749px)에서 각 상세 페이지의 첫 화면과 스크롤 1회 화면을 직접 봤습니다. 모든 수치는 눈대중이라 "대략"입니다. 못 본 것은 "미확인"으로 적었습니다. 사이트 문구는 옮기지 않고 요약만 했습니다. 로그인·가입·다운로드·폼 제출은 하지 않았습니다. 비교 기준은 현재 SkillBite 상세 스크린샷(`screenshots/detail-before/detail-1440.png`)입니다.

## 사이트별 관찰

### 1. Raycast Store: GitHub 확장 (어두운 테마)
- 상단 영역: 위에 떠 있는 캡슐형 메뉴 아래, 큰 여백(대략 120px)을 두고 아이콘(대략 96px, 둥근 상자) + 이름(대략 20px) + 한 줄 설명(대략 15px 회색) + 만든 사람·설치 수·종류 한 줄. 상단 영역 높이는 대략 300px로 여유가 많아 밀도는 낮음.
- 버튼: 오른쪽 위에 '설치' 채움 버튼(밝은 회백색, 대략 높이 40px, 폭 135px, 모서리 약 8px) 하나와 작은 화살표 보조 버튼. 주 행동이 화면 오른쪽에 고정된 위치임.
- 구조: 탭 3개(개요/명령/버전 기록)가 둥근 캡슐 안에 있음. 그 아래 스크린샷 3장이 가로로 나란히 있고, 그 아래에 구분선 한 줄 후 본문.
- 본문 폭: 대략 780~880px(왼쪽 150px에서 시작). 오른쪽에 대략 220px 폭의 기여자 목록 열이 따로 있음.
- 글자: 본문 대략 16px, 본문 안 제목 대략 32px(약 2배), 문서 제목 대략 36px. 줄 간격이 넉넉함(대략 24px). 단락 사이 여백이 큼(대략 40px).
- 구분선: 스크린샷 줄과 본문 사이에 얇은 선 1개만. 섹션 제목 사이에는 선 없이 여백으로 구분.
- 코드·링크: 링크는 파랑, 번호 목록은 일반 숫자 목록(원형 배지 없음). 이 화면에서 코드 상자는 못 봄(미확인).
- 안심·경고 박스: 못 봄(미확인).

### 2. VS Code Marketplace: Prettier 확장 (밝은 테마)
- 상단 영역: 검정 상단바 아래 폭 가득한 노랑 띠(높이 대략 220px). 안에 아이콘(대략 130px 정사각형) + 이름(대략 26px 굵게) + 만든 사람·설치 수·별점·무료 한 줄 + 한 줄 설명 + 초록 '설치' 버튼(대략 120x32px, 모서리 거의 각짐). 상단 영역이 한 덩어리로 묶여 있고 정보 밀도는 높음.
- 본문 구조: 탭(개요/버전 기록/Q&A/리뷰) 밑줄형. 왼쪽 본문 대략 710px, 오른쪽 사이드(분류, 태그, 링크, 정보 표) 대략 330px의 2열.
- 본문 글자: 본문 대략 14px, 섹션 제목 대략 22px 굵게(약 1.6배), 제목 아래 얇은 회색 선 1줄.
- 섹션 간격: 대략 40~50px. 단락 간격 대략 20px로 촘촘함.
- 코드 표시: 한 줄 명령어도, 설정 코드도 연한 회색 면(대략 #F4F4F4) 상자에 고정폭 글꼴. 테두리 없음, 모서리 거의 각짐, 복사 버튼은 보이지 않음. 문장 속 코드는 작은 고정폭 글자만.
- 설치 단계: 번호 배지나 스크린샷 없이 "이렇게 설치, 또는 이 명령어로 설치"를 문장 + 코드 상자로 설명. 시각적으로 단계라기보다 문서 느낌.
- 안심·경고: 본문에서 "Note:"를 굵은 글씨로만 표시했고 색 면이나 테두리 박스는 없음. 사이드의 '문제 신고' 링크는 작은 글자.
- 사이드 정보 표: 값 이름은 회색, 값은 검정의 2열 표로 선 없이 정렬.

### 3. GitHub Marketplace: Checkout 액션 (어두운 테마, 로그인 상태)
- 상단 영역: 한 줄. 작은 아이콘(대략 40px) + 이름(대략 20px) + 작은 알약 라벨('Actions') 왼쪽, 오른쪽에 '별표' 버튼과 초록 '최신 버전 사용' 분할 버튼(대략 높이 32px, 폭 175px). 매우 낮은 밀도 높이(대략 60px)로 바로 본문이 시작됨.
- 구조: 왼쪽 본문 카드(대략 965px)는 옅은 테두리 + 모서리 대략 6px 상자 안에 들어 있고, 오른쪽 사이드(대략 290px)는 상자 없이 제목 + 글 + 구분 없이 쌓임('소개', '인증됨', '태그', '기여자', '자료').
- 본문 글자: 본문 대략 14px, 본문 제목 대략 32px 굵게(약 2.3배)로 제목 아래 얇은 선. 섹션 간격 대략 30~40px로 촘촘함.
- 코드 표시: 문장 안의 코드는 짙은 회색 면 + 고정폭 글자 작은 칩. 코드 블록은 이 화면에서 못 봄(미확인).
- 안심 표시: 사이드의 '인증됨' 항목이 파랑 체크 아이콘 + 제목 + 짧은 설명 문장. 색 면 박스가 아니라 글자와 아이콘만 사용.
- 경고성 문장("위험을 확인한 뒤 옵션을 켜세요")도 박스 없이 일반 목록 문장 안에 링크로 넣음.

### 4. npm: zod 패키지 (밝은 테마)
- 맨 위에 연한 노랑 경고 띠(공지, 닫기 가능)와 주황~보라 그라데이션 줄 1개. 이어서 메뉴 줄, 검색창 줄이 각각 대략 60~90px 높이로 쌓여 첫 화면의 상단이 대략 220px를 차지함.
- 패키지 헤더: 이름(대략 22px 굵은 고정폭 느낌) + 'TS' 작은 아이콘, 아래 버전·공개·게시 시기를 작은 고정폭 글자 한 줄. 상단 영역은 단순하고 낮음.
- 탭: 5개(Readme/Code/의존성/Dependents/버전)가 폭 가득, 탭마다 다른 색 밑줄과 글자색(빨강, 보라, 파랑 등). 현재 탭은 연한 노랑 면. 다채롭지만 정돈된 편.
- 본문: 왼쪽 본문 대략 730px, 오른쪽 사이드 대략 360px. 사이드 맨 위에 '설치' 제목 + 한 줄 명령어 상자(`npm i zod`) 가 있고 오른쪽 끝에 작은 복사 아이콘. 명령어 상자는 흰 바탕 + 옅은 회색 테두리 + 모서리 대략 3px, 높이 대략 45px. 명령어가 본문에 묻히지 않고 항상 오른쪽 위에 보인다는 점이 핵심.
- 사이드 구분: 항목(저장소, 홈페이지 등) 사이 얇은 회색 구분선 1줄씩.
- 안심·경고 박스: 첫 화면에서는 위 공지 띠만 봄. 본문 속 박스는 미확인.
- 설치 단계: 단계 번호 없음. 명령어 한 줄이 전부.

### 5. 미리캔버스 템플릿 상세 (국내, 밝은 테마, 팝업형)
- 상세가 목록 위에 뜨는 창(폭 대략 1010px, 모서리 대략 16px)으로 열림. 뒤는 어둡게 처리. 오른쪽 위에 닫기(X).
- 구성: 왼쪽에 큰 미리보기 이미지(대략 565x320px, 옅은 테두리) + 그 아래 쪽 넘김 썸네일 4개. 오른쪽(대략 355px)에 제목(대략 20px) + 한 줄 규격 정보(대략 14px 회색) + 버튼 줄 + 분류 칩.
- 버튼: '이 템플릿 사용하기' 하나만 채움(청록, 폭 260px, 높이 40px, 모서리 약 6px). 옆의 링크 복사·찜은 정사각형 테두리 아이콘 버튼. 채움 버튼 1개 + 보조 아이콘 규칙이 분명함.
- 칩: 분류 8개를 테두리 알약으로. 색 면 없음.
- 아래에 '비슷한 템플릿' 카드 4열(칸 사이 대략 16px). 상세 안에서 다음 행동을 계속 이어 줌.
- 설치 단계·안심 박스·코드: 해당 없음(관찰 안 됨). 사용 방법 설명은 없고 이미지로 모든 걸 전달함.
- 홍보 팝업이 처음에 화면 중앙을 가려 첫 인상이 방해됨. 닫기 버튼은 보조 크기로 작음.

## 현재 SkillBite 상세와의 비교 (스크린샷 기준)
- 본문 폭: SkillBite 본문은 대략 800px(1440 중앙), Raycast 본문 대략 780~880px, VS Code 대략 710px, npm 대략 730px로 비슷한 범위. 폭 자체는 문제 없음.
- 제목 대 본문: SkillBite 페이지 제목 대략 28px, 섹션 제목 대략 22px, 본문 대략 14px. 참고 사이트의 섹션 제목은 본문의 약 1.6~2.3배로 비슷하거나 더 큼.
- 상단 영역: 참고 사이트는 한 덩어리(아이콘 + 이름 + 설명 + 주 버튼)를 오른쪽 또는 같은 줄에 압축. SkillBite는 아이콘, 라벨, 제목, 설명, '로그인 필요' 칩, 다운로드 버튼, 안내가 세로로 쌓여 대략 330px 높이.
- 구분: 참고 사이트는 섹션 제목 아래 얇은 선 1줄 또는 여백만 사용. SkillBite는 박스(초록 면, 테두리 상자, 노랑 면, 표 상자, 질문 목록 상자, 마무리 상자)가 한 화면에 6종 겹침.
- 코드 표시: 참고 사이트는 연한 회색 면 또는 흰 바탕 + 옅은 테두리 한 줄(복사 아이콘은 작게). SkillBite는 짙은 검정 상자 + '복사' 글자 버튼으로 가장 무거운 요소가 됨.
- 안심 박스: 참고 사이트는 박스 없이 아이콘 + 글자(GitHub '인증됨') 또는 굵은 "Note:"만 씀. SkillBite는 큰 초록 면 박스 + 방패 아이콘 + 소제목 + 3줄 + 접힘 목록.
- 설치 단계: 번호 배지(남색 원)는 참고 사이트에는 없었음(모두 문장 + 명령어). 필요한 단계만 번호를 쓰는 것은 괜찮지만, 단계 안에 하위 번호(1~4)와 접힘 박스, 보조 안내가 중첩됨.

## 가져올 시각 규칙 8개
1. 상단 영역은 한 덩어리로 압축합니다. 아이콘 + 이름 + 한 줄 설명을 왼쪽에, 주 버튼(다운로드)은 같은 줄 오른쪽에 둡니다(Raycast, GitHub처럼). 상단 높이는 대략 200px 안으로 줄이고, 다운로드 버튼이 첫 화면 어디서나 같은 위치에 보이게 합니다.
2. 본문은 대략 720~800px 한 칸으로 하되, 오른쪽에 좁은 사이드 열(대략 280~320px)에 '파일 정보'(크기, 형식, 필요 환경)와 다운로드 버튼을 두는 2열을 검토합니다(VS Code, npm, GitHub 공통). 모바일에서는 1열로 합칩니다.
3. 섹션 제목은 본문의 약 1.5~2배(예: 본문 16px이면 24~28px)로 하고, 제목 아래에 얇은 회색 선 1줄만 둡니다. 섹션을 박스로 감싸지 않고 여백(대략 40~56px)으로 나눕니다.
4. 박스는 종류를 줄입니다. 면 색 박스는 정말 중요한 경고 1종류, 그 밖의 정보는 테두리 없는 글자 또는 얇은 선 1종류만 씁니다(VS Code의 "Note:", GitHub '인증됨' 방식).
5. 안심 안내는 큰 색 면 박스 대신 체크 아이콘 + 굵은 한 줄 + 짧은 보충 문장으로 줄이고, 자세한 내용은 접어 둡니다(GitHub '인증됨' 방식).
6. 명령어는 한 줄 상자 하나로 통일합니다. 옅은 면 또는 흰 바탕 + 옅은 테두리, 고정폭 글꼴, 오른쪽 끝에 작은 복사 아이콘(npm 방식). 짙은 검정 상자는 쓰지 않거나 한 곳으로 제한합니다.
7. 설치 단계는 번호가 꼭 필요한 큰 단계(4개)만 번호로 하고, 단계 안의 하위 목록은 일반 글 + 필요한 코드 상자 하나로 단순화합니다. 단계 안에 박스를 중첩하지 않습니다.
8. 버튼은 채움 1종류(주 행동)와 작은 테두리 버튼(보조)만 씁니다. 한 화면에 채움 버튼이 반복돼도(상단, 하단) 같은 모양과 같은 문구로 통일합니다(미리캔버스: 채움 1개 + 아이콘 보조).

## 피할 시각 패턴 5개
1. 한 화면에 박스 모양 6종 이상(색 면, 테두리 상자, 표 상자, 접힘 상자, 목록 상자, 마무리 상자)을 섞는 것. 참고 사이트는 박스를 거의 쓰지 않고 선과 여백으로 나눴습니다.
2. 큰 색 면 박스(초록, 노랑)를 안내마다 쓰는 것. 색 면은 강조의 의미가 사라집니다.
3. 짙은 검정 코드 상자를 화면 가운데에 크게 놓는 것. 화면에서 가장 무거운 요소가 되어 눈이 거기만 갑니다.
4. 모든 단계에 원형 번호 배지, 하위 번호, 접힘 안내를 겹치는 것(과한 장식 + 중첩).
5. 본문 속 홍보성 표시(칩, 알약 라벨)를 여러 개 두는 것. 정보가 아닌 장식으로 읽힙니다.

## 현재 SkillBite 상세에서 AI 티가 나는 곳 5개와 고칠 방향
1. 초록 '받은 파일은 글자로 된 지침입니다' 박스(방패 아이콘 + 굵은 소제목 + 3줄 + 접힘 목록): 요즘 AI 화면에서 자주 보이는 '안심 박스' 공식입니다. 고칠 방향: 체크 아이콘 + 한 줄 + 짧은 보충으로 줄이고, 자세한 설명은 '파일 내용 미리보기' 링크 하나에 합칩니다. 색 면은 쓰지 않거나 아주 옅게 합니다.
2. 같은 화면에 박스 종류가 6가지(초록 면, 테두리 예시 상자, 표 상자(노랑 줄 포함), 노랑 접힘 상자, 질문 목록 상자, 마무리 CTA 상자): 모든 섹션을 카드로 감싸는 템플릿 습관입니다. 고칠 방향: 섹션은 제목 + 얇은 선 + 여백으로 나누고, 박스는 경고 1종류와 코드 1종류만 남깁니다.
3. 원형 남색 번호 배지(1~4) + 하위 번호(1~4) + 노랑 접힘 상자가 중첩된 설치 단계: 장식이 정보보다 많아 보입니다. 고칠 방향: 번호 배지를 작게 하거나 일반 번호 글자로 바꾸고, 하위 번호는 글로 풀거나 꼭 필요한 한 줄로 줄이며 '찾을 수 없습니다' 같은 예외 안내는 FAQ로 옮깁니다.
3-1. (같은 항목 보충) 맥/윈도우 선택 알약 버튼이 첫 단계 앞에 따로 떠 있는 것도 장식 느낌이 납니다. 탭 밑줄형으로 바꾸면 더 문서다워집니다.
4. 짙은 검정 코드 상자 + '복사' 글자 버튼 2개: 페이지에서 가장 무겁고, 코드 상자 안 여백이 커 위젯처럼 보입니다. 고칠 방향: 옅은 회색 또는 흰 바탕 + 옅은 테두리, 높이를 줄이고 복사는 작은 아이콘 + '복사됨' 피드백으로 바꿉니다.
5. 상단 영역 세로 나열과 반복되는 CTA(카테고리 칩, 큰 제목, 설명, '네이버 로그인 필요' 칩, 큰 남색 다운로드 버튼, 작은 안내 글, 마지막에 같은 CTA 한 번 더 큰 카드로 반복): 랜딩페이지 공식 구성입니다. 고칠 방향: 상단은 아이콘 + 제목 + 한 줄 설명 + 오른쪽 다운로드로 압축하고, '로그인 필요'는 준비물 섹션으로 옮기며, 마무리 CTA 큰 카드는 없애거나 한 줄 링크로 줄입니다.

## 한계
- Raycast와 npm은 본문 아래쪽(설치 방법 등), GitHub와 미리캔버스는 첫 화면 위주로만 봐서 코드 블록·경고 박스 표현은 VS Code에서만 확인했습니다. 나머지는 "미확인"입니다.
- GitHub은 로그인된 상태 화면이었고, 미리캔버스는 별도 페이지가 아닌 팝업형이었습니다.
- 글자 크기와 여백 수치는 스크린샷에서 눈대중으로 잰 값입니다. 정확한 값이 필요하면 개발자 도구로 재야 합니다.
- 모바일(좁은 화면)은 보지 않았습니다. 스크린샷 파일은 저장소에 넣지 않았습니다.
