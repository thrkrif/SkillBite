# 상세 화면 2라운드 리뷰 (Claude 리뷰 에이전트)

대상: `/skills/blog-writer-naver` 상세. 본 것: 스크린샷 4장(1440·768·390·320), `[id].astro`, SafetyBox·FeatureTable·Steps·Faq·CodeBox, `global.css`, `skills.json`. 기존 리뷰와 research는 읽지 않았다.
주의: 390·320 스크린샷은 폭 500px 캡처라 실제 좁은 폭의 가로 넘침은 코드로만 추정했다. 1440 캡처는 2700px에서 잘려 하단 CTA와 푸터가 보이지 않는다.

## 항목별 근거

1. AI 티 없음 (3점). 그라데이션, 글로우, 이모지 장식은 없다. 다만 h2(28px 굵게) + 본문 + 가는 구분선을 6번 같은 틀로 반복하고, 연한 파랑 둥근 사각형 안에 연필 아이콘을 넣은 제목부가 일반적인 SaaS 템플릿처럼 보인다. 아래 "AI 티" 참고.
2. 위계 (4점). h1 36px, 부제 17px 회색, 카테고리 14px로 차이가 분명하다. 다운로드 버튼이 사이드바 맨 위의 유일한 채운 색 요소라 눈이 먼저 간다. 감점: h2 6개가 모두 같은 크기·굵기라 "설치"와 "기능별 필요한 것"의 중요도가 같아 보인다. 설치 3단계 안에 하위 목록, 접이식, 메모 두 줄이 한꺼번에 있어 위계가 무너진다.
3. 여백과 리듬 (3점). 섹션 간격 64px, 항목 간격 32px처럼 규칙은 있다. 그러나 1440에서 사이드바 오른쪽 끝(약 1200px)이 헤더 메뉴 오른쪽 끝(약 1280px)과 맞지 않고, 본문 왼쪽은 헤더 로고와 맞는다. 오른쪽에 80px 정도의 의도 없는 빈 폭이 남는다. 사이드바 카드는 본문 앞 두 섹션 높이만큼만 차지하고 그 아래 오른쪽은 계속 비어 있다(sticky라 스크롤하면 따라오지만 정지 화면은 한쪽으로 쏠려 보인다). 768에서는 요약 카드가 가로 전체를 쓰며 버튼이 700px 넘게 늘어나 균형이 깨진다.
4. 브랜드 일치 (4점). 네이비 버튼·번호, 회흑 텍스트, Pretendard가 일관된다. 로고 노랑은 헤더 로고에만 있고 본문에는 없다. 정해진 색 밖의 파랑·보라는 없다(`--accent-soft`는 네이비 계열 연한 색). 로고에 의존한 디자인은 없다.
5. 신뢰 (4점). 가짜 평점·다운로드 수·후기가 없다. 예시 카드에 "구성 예시 · 실제 실행 결과가 아닙니다"를 표시했고, 윈도우는 "준비 중"으로 막았다. "무료 · 가입 없음"도 반복해 명확하다. 감점 이유는 아래 "그 외 문제"의 확인되지 않은 값 항목.
6. 운영 사이트 완성도 (3점). 건너뛰기 링크, `:focus-visible`, 44px 터치 영역, reduced-motion 처리, 복사 버튼의 `role="status"`는 좋다. 푸터(브랜드 + 메뉴 2개 + 한 줄 소개)가 얇아 연락처·피드백·운영자 정보가 없다(피드백 URL은 `[확인 필요]`라고 알고 있으나 화면에는 자리 표시도 없다). 404, OG, 파비콘, 로딩 속도는 이 자료로는 미확인.
7. 반응형 (4점). 768에서 1열로 바뀌고 표는 479px 이하에서 카드형으로 바뀐다. 코드 박스는 `pre-wrap`+`overflow-wrap:anywhere`로 줄바꿈한다. 390 이미지에서 가로 넘침은 보이지 않는다. 320의 `/blog-writer-naver [내용]` 박스에서 "복사" 버튼이 코드 옆에 붙은 채로 두 줄로 접혀 괜찮다. 실제 320px 뷰포트 직접 확인은 미확인이라 5점은 주지 않았다.
8. 비개발자 이해도 (3점). 상단에서 제목, 한 줄 요약, 다운로드, 명령어, 필요한 것까지 5초 안에 파악할 수 있다. 감점: "어떻게 쓰는지"가 페이지 중간 이후(설치 4단계)에 있고, 그 앞에 "결과물 구성 예시", "받은 파일은 글자로 된 지침"이 먼저 온다. 설치 3단계가 숨김 폴더, 폴더로 이동, 단축키(`⇧ + ⌘ + G`), 터미널까지 요구해 비개발자에게 가장 무거운 구간이다.

## AI 티가 나는 곳 (5개)

1. 제목부의 아이콘 칩. 근거: 연한 파랑(`--accent-soft`) 둥근 사각형 + 얇은 선 연필 아이콘, 왼쪽에 놓은 구조는 AI가 만든 SaaS 템플릿의 전형이다. 아이콘이 내용(블로그 글쓰기)에 새로운 정보를 주지 못하고 카테고리 14px 글자가 같은 일을 한다. 고칠 방향: 아이콘 칩을 빼고 카테고리·제목·부제만 두거나, 스킬마다 다른 실제 서비스 로고·결과물 일부를 쓴다.
2. 모든 섹션이 같은 틀(굵은 h2 + 회색 문단 + 가는 선)이고 섹션 사이를 같은 64px로 띄운다. 근거: 스크린샷에서 "결과물 / 받은 파일 / 기능별 / 설치 / 막히는 점"이 크기·색·밀도 차이 없이 한 줄로 이어진다. 중요한 것(설치)과 보조 정보(파일 안전)의 무게가 같아 템플릿처럼 보인다. 고칠 방향: 설치를 가장 크게(번호 큰 단계 카드) 하고, 안전 설명·기능 표는 더 작고 가볍게 하거나 사이드바·접이식으로 내린다. 섹션 순서도 "설치 → 결과물 예시 → 안전 → 기능"처럼 사용 흐름으로 바꾼다.
3. "무료 · 가입 없음 · ZIP 파일 1개"를 위(사이드바)와 아래(끝 CTA)에 똑같은 문구와 똑같은 버튼으로 반복한다. 근거: 하단 CTA 줄이 끝 구분선 + 버튼 + 회색 문구로 구성되어 랜딩 페이지 템플릿의 "마지막 CTA 배너" 공식이다. 데스크톱에서는 한 화면 거리 안에서 사이드바가 이미 따라오므로 중복이다. 고칠 방향: 데스크톱에서는 하단 CTA를 빼거나, 다음에 할 일("다른 스킬 보기" 등)로 바꾼다.
4. 접힘 요소와 장식 기호의 반복. 근거: FAQ의 `+/−`, 파일 보기의 `▸`, 문제 해결의 `▶`가 서로 다른 기호·위치로 섞여 있다(FAQ는 오른쪽 +, 나머지는 왼쪽 삼각형). 같은 "펼치기"인데 규칙이 없어 생성한 조각을 모은 느낌이 난다. 고칠 방향: 하나의 펼침 표시(위치·기호)로 통일한다.
5. 예시 카드의 "제목/도입/본문/마무리" 라벨 + 설명 문장. 근거: 실제 글이 아니라 "~합니다"로 끝나는 설명문이고 문구가 일반적이라 AI가 쓴 샘플 문단처럼 읽힌다. "구성 예시" 라벨로 정직하게 표시한 점은 좋지만 시각적으로는 빈 틀이다. 고칠 방향: 실제 스킬 실행 스크린샷·결과 글 일부로 교체하거나(열린 항목에 이미 있음), 교체 전까지는 카드 크기를 줄여 설치 뒤로 보낸다.

## 그 외 문제

접근성
- 설치 3단계 안에 번호 목록(1~4)이 중첩되어 있고, "2번에서 압축을 푼…", "위의 1번부터 다시 따라 합니다"가 바깥 단계인지 안쪽 번호인지 모호하다. 스크린 리더와 눈 모두 혼동한다. 하위 목록 번호를 "가, 나"로 바꾸거나 단계 이름으로 지칭한다.
- 복사 버튼은 화면에 "복사"만 보이고 접근 이름은 "{명령어} 복사"다. 이름에 보이는 글자가 포함되어 문제는 없다. 다만 한 화면에 3개가 있어 상태 메시지("복사했어요")가 버튼 아래 별도 줄로 생겨 레이아웃이 밀린다(동작은 미확인).
- 본문 보조 글자(`.meta` 14px, `--text-mute` #6e6e69)는 흰 배경에서 대비가 약 5:1로 기준은 넘지만 14px의 얇은 회색이 긴 안내문(설치 아래 두 줄)에 쓰여 읽기 어렵다. 앱 재시작 안내는 중요한 내용이라 14px 회색은 적절치 않다.
- 사이드바 `<aside>`가 본문보다 앞에 있어 키보드 사용자가 본문 전에 다운로드·복사 버튼을 먼저 만난다. 허용 가능하지만 건너뛰기 링크는 메인 시작으로만 간다(상세 안 점프는 미확인).
- 운영체제 탭은 `aria-pressed` 버튼이다. 탭 패턴(`role=tab`)이 아니라서 괜찮지만, 윈도우를 눌러도 "[확인 필요]"만 나오는 빈 탭이라 JS가 있을 때만 나타난다는 점이 의도된 것인지는 미확인.

확인되지 않은 값의 표시
- 설치 경로 `~/.claude/skills`와 "다시 켜지 않아도 폴더를 넣자마자 바로 쓸 수 있습니다", FAQ의 "앱을 다시 켤 필요는 없고, 폴더를 넣으면 바로 나타납니다"는 단정형으로 쓰여 있다. `AGENTS.md` 지침상 재시작 여부는 확인 전까지 `[확인 필요]`로 두어야 한다. 이 값이 실제로 확인된 것인지는 `install.js`와 근거 문서를 보지 않아 미확인이다. 화면에는 확인 표시가 없으므로 확인되었다면 근거 날짜를, 아니라면 자리표시를 두는 편이 안전하다.
- 같은 스킬 JSON의 다른 항목(티스토리 FAQ, 한글 변환 등)에는 `[확인 필요]`가 본문 문장에 그대로 섞여 있다. 이번 스킬(네이버)에는 없지만, 그 스킬 상세 화면에서는 대괄호가 문장 속에 그대로 노출되어 미완성처럼 보일 수 있다(화면은 미확인).
- 윈도우 안내는 "준비 중이에요"(상단)와 탭 안 "[확인 필요]"(PENDING)가 서로 다른 말투로 표시된다. 한 표현으로 통일한다.

좁은 폭
- 390·320에서 h1이 "네이버 블로그 글 자동 / 작성"처럼 단어 중간에서 끊긴다(320 이미지). `word-break: keep-all`이 있어도 `overflow-wrap:anywhere` 때문에 끊긴다. 짧은 제목은 괜찮지만 긴 제목이 늘면 어색해진다.
- 320에서 요약 카드(안쪽 여백 24px)가 좁아 "필요한 것" 목록이 줄바꿈이 많다. 모바일에서는 요약 카드가 본문 전에 약 한 화면을 다 차지해 설치 안내가 한참 아래로 밀린다. "필요한 것"을 접거나 본문 아래로 내리는 것을 검토한다.
- 모바일 페이지 길이가 약 4400px(500폭 캡처 기준)이다. 설치 3단계가 가장 길어 한 번에 읽기 부담스럽다.

기타
- 사이드바 "필요한 것"에 `requirements`와 `tags`를 같은 목록으로 합쳐서 "네이버 로그인 필요"가 기기·요금제 조건과 섞여 보인다(데이터상 tags가 카드용 라벨인 듯하나 의도는 모름).
- 말투가 "~합니다"(본문)와 "~이에요/요"(사이드바 "글자로만 된 파일이에요", 설치 소개)로 섞여 있다. `AGENTS.md`의 "존댓말, 쉬운 말" 범위 안이지만 한 가지로 맞추면 더 단정해 보인다.
- 푸터, 하단 CTA, 404, OG, 파비콘, 로딩 속도: 이번 자료로 미확인.
