## 2. 항목별 근거

**1. AI 티 없음 — 3점.** 그라데이션·글로우·이모지는 없고 장식이 절제돼 있다. 감점 이유는 3절에 적었다. 요약하면 모든 섹션이 같은 H2 + 같은 간격으로 반복되고, 결과물 자리에 합성한 예시가 들어가 있고, 오른쪽 카드가 SaaS 가격 카드 형식이다.

**2. 위계 — 3점.** 1440에서 H1(36px)과 H2(28px)의 차이가 작다. 본문 H2 "이런 결과물이 나옵니다"도 제목처럼 크게 보여 H1과 경쟁한다. 반면 가장 눈에 띄는 요소는 사이드바의 남색 버튼이라 "받는 것"이 첫 행동으로 분명하다. 카테고리 → 제목 → 부제 순서는 자연스럽다. 본문 안에서는 H2가 7개 섹션에 같은 크기로 이어져 중요도 구분이 없다. 설치 단계가 가장 중요한데도 결과물 예시, 안전 설명, 기능 표보다 아래에 있다.

**3. 여백과 리듬 — 3점.** 섹션 간격 64px, 제목 아래 24px로 일정하다. 다만 일정하기만 해서 단조롭다. 1440에서 본문은 680px에서 끝나고 오른쪽에 사이드바가 짧게 붙어 있어, 사이드바 아래로 긴 빈 열이 생긴다(sticky라 스크롤 중에는 보완됨, 정지 상태 스크린샷에서는 빈 곳). 390에서는 아이콘이 혼자 한 줄을 차지해 제목이 아래로 밀린다. 스킬이 1개일 때(목록 쪽 문제)는 이 화면과 무관하다.

**4. 브랜드 일치 — 4점.** 남색 `#1F3A5F` 버튼, 회흑 텍스트, Pretendard가 일관되다. 정해진 색 밖의 파랑·보라는 안 보인다. 연한 남색 아이콘 타일(`--accent-soft`)이 쓰이는데 이것이 로고의 노랑과 이어지는 요소는 화면에 없다. 로고만 노랑이고 나머지는 남색·회색이라 브랜드 색이 헤더 로고에만 남는다.

**5. 신뢰 — 4점.** 가짜 평점·다운로드 수·후기는 없다. 예시 카드에 "구성 예시 · 실제 실행 결과가 아닙니다"를 명시한 것은 좋다. "무료 · 가입 없음 · ZIP 파일 1개"가 버튼 바로 아래에 있다. 데이터에는 `[확인 필요]`가 쓰이고(티스토리·한글 스킬), 윈도우 탭은 코드상 `PENDING` 자리표시를 쓴다. 단, 윈도우 탭 화면은 스크린샷에 없어 **미확인**. 감점: "앱을 다시 켜야 하나요? 다시 켜지 않아도 폴더를 넣자마자 바로 쓸 수 있습니다"라는 단정이 FAQ에도 반복되는데 이 값이 확인된 것인지 화면에서 알 수 없다(AGENTS.md는 재시작 여부를 확인 전에 단정하지 말라고 한다. 근거 표시가 없다).

**6. 운영 사이트 완성도 — 3점.** 헤더·푸터·내비는 있다. 푸터는 로고와 링크 두 개, 한 줄 소개뿐이다(1440 캡처에는 푸터가 잘려 있어 **미확인**). 404, OG 미리보기, 파비콘, 로딩 속도는 이 범위로 **미확인**. 포커스 링은 전역 `:focus-visible`(2px, 3px 오프셋)로 있고 키보드 이동이 가능하다. 문제: "파일 내용 보기" summary에 마커가 없어 열리는 요소로 보이지 않는다(4절). 대비는 `--text-mute #6e6e69`를 흰 배경 14px에 쓰는데 약 5:1로 통과 수준이나 여유가 적다.

**7. 반응형 — 3점.** 320에서 코드 박스의 `/blog-writer-naver [내용]`이 `[L`에서 잘린다(`white-space: pre` + 박스 내부 스크롤). 사이드바 안의 같은 명령어는 줄바꿈되어 두 곳이 서로 다르게 동작한다. 모든 본문에서 한국어가 단어 중간에서 끊긴다(4절). 390·320에서 제목·표·단계는 넘침 없이 보인다. 페이지 자체의 가로 넘침은 캡처 한계로 **미확인**. 768은 1열로 자연스럽다.

**8. 비개발자 이해도 — 3점.** 상단 5초 안에 "네이버 블로그 글 자동 작성 / 내용만 입력하면 글을 쓰고 게시까지 도와줍니다 / 무료 / 다운로드"는 읽힌다. 그러나 사이드바의 "필요한 것"에 "Claude 데스크톱 앱 또는 터미널", "브라우저 제어 도구"가 나오는 순간 비개발자에게 어려워진다. 설치는 4단계라고 해놓고 3단계 안에 소단계 4개와 접힌 문제해결이 있어 실제로는 10단계 이상이다. 결과물 영역에 실제 결과가 없고 구성 설명뿐이라 "무엇을 받는지"가 약하다.

## 3. AI가 만든 것처럼 보이는 곳

1. **결과물 자리에 들어간 합성 예시 카드.**
   - 근거: 1440 스크린샷 `이런 결과물이 나옵니다` 아래 카드. "블로그 글의 구성을 먼저 살펴보세요."라는 제목은 결과물이 아니라 안내 문구이고, 내용도 베란다 텃밭이라는 생성형 문장 같은 샘플이다. 라벨-본문 2열 그리드(제목·도입·본문·마무리)는 템플릿 형태다.
   - 방향: 실제 실행 결과(스크린샷 또는 실제 글 한 편의 일부)로 교체한다. 없으면 이 섹션을 설치 아래로 내리거나 제거한다. 지금처럼 가장 위에 가짜 자리를 두지 않는다.

2. **모든 섹션이 같은 틀로 반복되는 문서 구조와 같은 문장 습관.**
   - 근거: H2 7개가 같은 크기·같은 64px 간격이다. 설명 문장은 "~입니다/~합니다" 해설체가 이어지고, 설치 단계는 전부 굵은 "**동사를 합니다.** 설명" 패턴이다. "보이지 않는 것이 정상입니다"가 3단계 본문과 FAQ에서 사실상 반복되고, FAQ 5개 중 3개가 설치 단계와 같은 내용이다. 이 중복은 문서를 채우려는 생성 느낌을 준다.
   - 방향: FAQ에서 설치 단계와 겹치는 항목(폴더 숨김, 폴더 없음, 이동 방법)은 삭제하고 서로 다른 질문만 남긴다. 섹션 우선순위를 두어 설치 단계는 크게, 보조 설명(안전·기능 표)은 작게 위계를 준다.

3. **SaaS 가격 카드 형태의 사이드바.**
   - 근거: 테두리 박스 안에 가로 꽉 찬 남색 버튼, 그 아래 작은 회색 "무료 · 가입 없음" 한 줄, 그 아래 라벨(명령어·필요한 것·파일)과 불릿 목록. 흔한 "스티키 CTA 카드" 템플릿이다. 또 "필요한 것" 목록이 `requirements`와 `tags`를 한 목록에 합쳐서("네이버 로그인 필요"가 요건처럼 같은 불릿에 섞임) 데이터 구조가 그대로 보인다.
   - 방향: 필요한 것은 사람이 쓴 문장으로 정리하고 태그는 따로 둔다. 파일 확인은 카드 밖의 본문 링크로 둔다. 카드의 정보를 줄여 버튼 + 명령어 + 요건 3가지만 남긴다.

4. **범용 아이콘 타일.**
   - 근거: 연한 남색 정사각 타일에 연필 선 아이콘. 390·320에서 혼자 한 줄을 차지한다. 스킬 내용을 설명해 주지도 않고 정보도 없다.
   - 방향: 크기를 줄이거나 제목 옆 인라인으로 옮기거나, 모바일에서는 제거한다. 로고가 노랑이므로 타일 색 선택도 다시 본다.

5. **"+" 텍스트 아코디언과 "-" 대체 글리프.** CSS로 `+`/`−`를 글자로 바꾸는 방식이라 템플릿의 FAQ 아코디언과 같다. 위 2번에서 FAQ를 줄이면 자연스럽게 해결된다.

## 4. 그 외 문제

**가독성·접근성**
- 한국어가 단어 중간에서 끊긴다. `p { overflow-wrap: anywhere }`가 `word-break: keep-all` 없이 본문에 걸려 있다(H1~H3만 keep-all). 390 스크린샷에서 "파/일이 저절로", "자동 입/력·게시", 320에서 "네이버 로그/인"이 보인다. 본문·표 셀에 `word-break: keep-all`을 쓰고, 긴 영문·경로만 `overflow-wrap: anywhere`로 둔다.
- "파일 내용 보기" `summary`가 `display: flex`라 열림 마커가 사라져 일반 굵은 글씨처럼 보인다(모든 해상도 스크린샷). 같은 화면의 "폴더를 찾을 수 없습니다" details는 삼각형이 있어 두 요소가 일관되지 않다. 마커나 `+`를 추가한다.
- 설치 3단계 안에서 1~4번 번호가 다시 시작되어 바깥 "3."과 안쪽 "3." "4."가 헷갈린다. 안쪽은 조건 분기(열렸다면/이미 있다면)인데 순서 번호로 보인다. 소단계를 글머리표나 소제목으로 바꾼다.
- 1440에서 키 표기 `⇧ + ⌘ + G`가 줄바꿈되며 `G )`가 다음 줄로 떨어진다. `kbd` 묶음에 `white-space: nowrap`을 쓴다.
- 코드 박스 `code`는 `overflow-x: auto`인 스크롤 영역인데 `tabindex`가 없다. 브라우저에 따라 키보드로 스크롤이 안 될 수 있다(**미확인**, Chrome 최신은 자동 포커스 가능).
- `복사` 버튼의 이름이 모두 "복사"로 같아서 스크린리더에서 어떤 코드의 복사인지 구분이 안 된다. `aria-label`에 "명령어 복사" 등을 구분해 넣는다.
- 안내용 `role="status"`가 코드 박스마다 있다(페이지에 4개). 동작에는 문제 없으나 중복 라이브 영역이다. **미확인**(실제 스크린리더 테스트 안 함).
- 대비: 본문 `#4d4d4a`, 보조 `#6e6e69`는 흰 배경에서 통과 수준이다. 코드 박스 배경 `#f5f5f2` 위의 `.copy` 글자(`--text-sub`)도 통과 추정. 계산 미실행이므로 **미확인**.

**확인되지 않은 값의 표시**
- 윈도우 탭은 기본 선택이 맥이라 스크린샷에 나오지 않는다. 코드상 `[확인 필요]`가 들어가는데, 윈도우 사용자는 탭을 눌러야만 막힌 곳을 알게 된다. 탭 라벨에 "준비 중"을 붙이거나 사이드바 요건에 "맥 기준"을 적는 것이 낫다. 실제 화면은 **미확인**.
- 재시작 여부 문구("다시 켜지 않아도 ... 바로 쓸 수 있습니다")가 확정 문장으로 나오고, FAQ에서도 같은 단정이 반복된다. 값의 출처가 화면에 없다. 확인 전이면 `[확인 필요]`로 둬야 한다는 AGENTS.md 기준에 비추어 점검이 필요하다(`install.js`의 `restartNote` 값은 읽지 않아 **미확인**).

**좁은 폭**
- 320에서 설치 4단계의 `/blog-writer-naver [내용]`이 잘리고 복사 버튼과 겹쳐 보인다. 사이드바(`white-space: normal`)와 달리 `.code code`가 `pre`라서 일관성이 없다. 두 곳을 같은 방식으로 맞춘다.
- 사이드바가 모바일에서 H1 바로 아래에 오고 그 뒤에 본문이 이어져, 사용자가 읽기 전에 요건과 명령어 박스를 먼저 만난다. 비개발자에게는 "결과물 → 다운로드 → 요건" 순서가 더 자연스러울 수 있다. 의견 수준.

**데스크톱 정렬**
- 1440에서 헤더 로고 왼쪽 선(x≈161px)과 본문·뒤로가기 왼쪽 선(x≈232px)이 맞지 않는다. 헤더는 1184px 컨테이너, 상세 본문은 1040px 컨테이너(`.container.detail`)를 써서 생긴 차이로 보인다. 헤더와 같은 컨테이너로 맞추거나 헤더도 같은 폭을 쓴다.

**마지막 CTA**
- 본문 끝 "스킬 파일 다운로드"는 버튼이 아니라 굵은 밑줄 링크 + 작은 회색 문구다(768·390 하단). 사이드바 버튼과 시각 무게가 크게 달라 긴 페이지를 다 읽은 사람이 다시 받을 때 눈에 안 띈다. 버튼 스타일로 통일한다.

## 5. 확인하지 못한 것

- 윈도우 탭 화면, 푸터 1440, 404, OG 이미지, 파비콘, 로딩 속도.
- 320에서 페이지 전체 가로 스크롤 여부(캡처가 500px iframe).
- 실제 키보드·스크린리더 조작, 색 대비 수치.
- 다른 스킬(결과물 이미지 있는 경우, 확인 필요 표기가 있는 스킬)의 상세 화면.
