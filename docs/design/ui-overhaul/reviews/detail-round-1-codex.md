### 항목별 근거

**1. AI 티 없음 — 3/5**

그라데이션·글로우·장식용 이모지가 없고, FAQ와 기능 표를 선과 글자로 정리한 점은 좋습니다. 다만 ‘제목·도입·본문·마무리’로 채운 추상적인 구성 예시, 반복되는 안심 설명, 내용량과 관계없이 이어지는 큰 구역 간격에서 생성형 템플릿의 인상이 남습니다.

**2. 위계 — 4/5**

1440px에서는 큰 제목 → 설명 → 네이비 다운로드 버튼으로 시선이 자연스럽게 이동합니다. 본문과 요약 사이드바의 역할도 분명합니다. 다만 모바일에서는 준비물·명령어까지 담은 긴 요약 상자를 모두 지나야 결과물을 볼 수 있습니다. 사용자가 가치를 이해하기 전에 설치 조건부터 읽게 됩니다.

**3. 여백과 리듬 — 3/5**

구역 간격과 FAQ 행의 규칙은 일정합니다. 그러나 짧은 파일 안내에도 큰 구역 간격을 적용하고, 설치 3단계에는 긴 설명과 중첩 목록을 몰아넣어 밀도가 불균형합니다. 1440px에서 본문과 사이드바 사이 64px 간격은 적절하지만, 아래쪽 긴 본문에서는 오른쪽 공간이 넓게 남습니다. 실제 스크롤 중 sticky 배치의 인상은 **미확인**입니다.

**4. 브랜드 일치 — 4/5**

네이비 버튼, 회흑 글자, 로고의 노랑이 일관되고 로고 모양에 과하게 의존하지 않습니다. Pretendard와 코드용 JetBrains Mono도 로컬 패키지에서 불러옵니다. 다만 상세 제목은 문서의 **40/30px**와 달리 실제로 **36/28px**를 적용합니다. 코드 박스 반경도 문서의 4px와 구현의 6px가 다릅니다. ### 그 외 문제

**접근성**

- **포커스:** 공통 `:focus-visible`의 2px 외곽선과 본문 건너뛰기 링크가 있습니다. 실제 탭 이동 시 잘림·가림 여부는 **미확인**입니다.
- **키보드:** FAQ는 기본 `<details>/<summary>`, 운영체제 선택은 `<button>`과 `aria-pressed`를 사용합니다. 기본 키보드 조작을 고려한 구조입니다. 운영체제 선택은 시각적으로 탭처럼 보이지만 구현은 버튼 그룹이므로, 화살표 이동을 지원하는 탭이라고 단정할 수 없습니다.
- **명령어:** 설치 영역의 가로 스크롤 코드에는 명시적인 키보드 포커스 처리가 없습니다. 키보드만으로 전체 문자열을 확인할 수 있는지는 **미확인**입니다. 복사 버튼의 이름도 모두 ‘복사’여서 ‘명령어 복사’, ‘설치 경로 복사’처럼 대상을 구분하면 좋습니다.
- **대비:** CSS 색상으로 계산한 대비는 보조 글자/흰색 약 **5.13:1**, 보조 글자/코드 배경 약 **4.69:1**, 흰 글자/네이비 버튼 약 **11.48:1**입니다. 이 조합들은 일반 텍스트 기준 4.5:1을 충족합니다. 모든 상호작용 상태의 대비는 **미확인**입니다.
- **펼치기 표시:** ‘파일 내용 보기’는 `summary`를 flex로 표시하면서 별도 펼침 표시가 없어 단순 텍스트처럼 보입니다. 펼침 여부를 드러내는 표시가 필요합니다.

**정보 정확성**

- 윈도우 설치 경로는 코드에서 `[확인 필요]`로 표시합니다. 다만 선택되지 않은 기본 화면에서는 다운로드 전에 윈도우 안내가 준비되지 않았다는 사실을 알기 어렵습니다.
- 맥 경로와 재시작 불필요는 `install.js`에 **직접 확인한 값으로 기록**되어 있습니다. 이를 미확인 값이라고 감점하지 않았습니다. 이번 리뷰에서 재현한 것은 아니며, 확인한 앱 버전과 환경 범위는 **미확인**입니다.
- ‘Claude 데스크톱 앱 또는 터미널’은 터미널만 있으면 되는 것으로 읽힐 수 있습니다. 확인된 제품·실행 환경을 구체적으로 적어야 합니다.
- 파일이 저절로 실행되지 않는다는 설명과 사용 중 작업의 안전성은 구분해야 합니다. 브라우저를 통한 게시 기능이 있으므로 파일 형식 설명만으로 모든 작업이 안전하다고 받아들여지지 않도록 문구를 조정하는 편이 좋습니다.

**좁은 폭과 문서 일치**

- 320px의 명령어 잘림은 우선 수정 대상입니다. 긴 명령어를 읽을 수 있도록 줄바꿈을 허용하거나 복사 버튼을 별도 행으로 배치하는 방향이 적절합니다.
- 320px 기능 표는 두 열보다 기능별 ‘기능 → 필요한 것’을 세로로 읽는 구성이 이해하기 쉽습니다.
- 390·320px의 오른쪽 빈 공간과 캡처 하단의 긴 공백은 iframe·캡처 영역의 영향일 수 있어 **사이트의 가로 넘침이나 불필요한 높이로 판정하지 않았습니다**.
- `DESIGN.md`는 설치 예외를 FAQ로 연결하도록 정했지만, 구현은 단계 안에 별도 펼침 영역을 두고 FAQ에도 같은 내용을 반복합니다. 문서와 구현을 맞출 필요가 있습니다.
