## 항목별 근거

1) AI 티 없음 (4/5). 그라데이션, 글로우, 유리 효과, 이모지가 없고 흰 바탕에 얇은 선 위주라 절제되어 있습니다. 다만 아래 "AI 티가 나는 곳"에 적은 몇 군데가 템플릿 느낌을 남깁니다.

2) 위계 (4/5). 52px 굵은 제목, 18px 부제, 24px 섹션 제목, 18px 스킬명으로 크기 차이가 분명하고 시선이 위에서 아래로 자연스럽게 흐릅니다. 다만 화면 전체에 "행동"(버튼)이 없어서 마지막 단계의 시선이 갈 곳이 없습니다.

3) 여백과 리듬 (3/5). 섹션 간격(80px, 40px, 20px)은 규칙이 있습니다. 하지만 스킬이 1개일 때 1440px에서는 카드 한 줄 아래가 휑하고, 제목에서 카드까지 "전체 1개" 줄이 끼어 있어 조금 어색합니다. 본문이 좌측 46rem에만 몰려 우측 절반이 비어 있습니다.

4) 브랜드 일치 (4/5). 노랑 #F5C842, 회흑 #242424, Pretendard가 일관되고 임의의 파랑·보라가 없습니다. 감점 이유는 노랑이 아이콘 칸과 선택된 필터에만 쓰여 브랜드 존재감이 약하다는 점, 헤더가 로고 이미지(/logo.svg)에 크게 의존한다는 점입니다.

5) 신뢰 (4/5). 가짜 평점, 다운로드 수, 후기가 없고 "무료, 가입 불필요, Claude 유료 구독 필요"를 솔직하게 밝혔습니다. 다만 푸터 문구 "AI와 함께 더 나은 일을 하는 작은 도구들을 모읍니다"는 누가 운영하는지 알려주지 않아 사실이 흐릿합니다.

6) 운영 사이트 완성도 (2/5). Base.astro에는 og:title, og:description, og:image, twitter 카드 메타가 전혀 없어 공유 미리보기가 비어 있습니다. canonical도 없습니다. 파비콘, 매니페스트, 건너뛰기 링크, 포커스 링, 푸터는 있어 좋습니다. 404 화면과 파비콘이 실제로 보이는지는 직접 확인하지 못했습니다(스크린샷에 없음). 색 대비는 소스상 #6e6e69 on 흰색이 약 5:1이라 통과로 보이지만 도구로 측정하지는 않았습니다.

7) 반응형 (4/5). 1440, 768, 390, 320 모두 눈에 띄는 가로 넘침과 글자 잘림이 없습니다. 768/390/320 이미지 오른쪽의 회색 띠가 실제 넘침인지 캡처 도구의 여백인지는 확인하지 못했습니다(페이지 본문은 회색 띠 안쪽에서 끝납니다). 320에서 `/blog-writer-naver 주제`가 "blog-writer-"와 "naver"로 어색하게 줄바꿈되고, 카드 제목도 "네이버 블로그 글 / 자동 작성"으로 좁게 접힙니다.

8) 비개발자 이해도 (3/5). 제목과 두 줄 설명으로 "AI에게 일을 알려주는 파일을 받아 쓴다"는 것은 전달됩니다. 그러나 5초 안에 "그래서 무엇을 주는가"가 구체적으로 보이지 않습니다. 결과물 예시(스크린샷)나 "블로그 글을 대신 써 드려요" 같은 구체적 약속이 없고, "스킬", "글자 파일", "Claude에 추가", "폴더를 안내에 따라 넣어주세요"는 비개발자에게 여전히 추상적입니다.

## AI 티가 나는 곳 (3개 이상)

1. 홈 3단계 섹션 (index.astro `.steps`, 1440 화면 하단). 윗줄 + 숫자 + 제목 + 한 줄 설명이 세 번 반복되는 전형적인 "3-step how it works" 템플릿 구성입니다. 문구도 "파일 받기 / Claude에 추가 / 명령어 입력"처럼 일반적이라 이 서비스만의 내용이 없습니다. 숫자 1, 2, 3이 14px 회색이라 장식도 정보도 아닙니다.
2. 스킬 아이콘 칸 (SkillRow.astro `.icon-surface`, home-many-1440). 모든 스킬이 똑같은 노란 사각형 + 연필 아이콘이라 목록이 늘어나면 "아이콘 붙은 카드 복제" 느낌이 강해지고 스킬을 구별하는 데 쓸모가 없습니다. 회의록, 엑셀, 이메일도 전부 연필입니다.
3. 반복 태그 (SkillRow.astro `.tags`, home-1440 카드). "글쓰기 / 쉬움 / 브라우저 필요" 같은 작은 테두리 태그를 모든 행에 똑같이 붙입니다. "쉬움"은 근거 없는 자체 평가라 장식에 가깝고, 모든 스킬에 같은 값이 나오면 정보 가치가 없습니다.
4. 히어로 (index.astro `.intro`, 1440 상단). 큰 굵은 제목 + 회색 설명 + 아무것도 없는 우측 여백은 스타터 템플릿의 히어로 공식입니다. 서비스 고유의 시각 요소(결과 화면, 실제 명령어 예시)가 없습니다.
5. 푸터 문구 (Base.astro). "AI와 함께 더 나은 일을 하는 작은 도구들을 모읍니다"는 어느 서비스에나 붙일 수 있는 생성형 문구 톤입니다.
6. 안내 문구 "새 스킬은 준비되는 대로 이곳에 추가돼요" (SkillList.astro `.note`). 스킬이 9개인 화면에서도 같은 문구가 남아 있어, 상황과 관계없이 붙는 안내처럼 보입니다.

## 가장 먼저 고칠 것 (우선순위)

1. 공유 미리보기와 운영 메타 추가. Base.astro에 og:title/description/image, twitter:card, canonical을 넣고 404 페이지를 확인하세요. 현재 점수가 가장 낮은 항목이고 수정 비용이 가장 작습니다.
2. 히어로에 구체적인 약속과 행동 추가. "블로그 글을 대신 써 드려요"처럼 결과가 보이는 한 문장과, 스킬 목록/사용 방법으로 가는 눈에 띄는 노란 버튼 또는 실제 명령어 예시 한 줄을 넣어 5초 이해도와 위계의 마지막 단계를 채우세요.
3. 반복 템플릿 요소 줄이기. 스킬별로 구별되는 아이콘(또는 아이콘 제거), 근거 없는 "쉬움" 태그 제거 또는 실제 기준 명시, 3단계 문구를 이 서비스의 실제 행동(예: 어느 메뉴에서 파일을 올리는지, `[확인 필요]` 포함)으로 구체화하세요.
