# 시험 실행 1회차 채점 (grade-r1)

채점 기준은 각 스킬의 `SKILL.md` 지침입니다. 실행 결과 파일에는 에이전트의 응답만 있고 실제 입력 원문은 없어서, 입력 내용은 응답과 "입력별 기대 동작"에서 추정했습니다. 추정이 필요한 곳은 그렇다고 적었습니다.

## 1. email-reply

| 입력 | 항목 | 판정 | 근거 |
| --- | --- | --- | --- |
| 1 거절 | 약속·날짜·금액을 지어내지 않음 | 합격 | 새 날짜·금액 없음. 「별도 견적으로 안내해 드리겠습니다」는 입력에 있던 대안(별도 견적)으로 보임 |
| 1 | '넣지 않은 것' 표시 | 합격 | 「※ 넣지 않은 것: 편집 가능 일정, 견적 금액(말씀하지 않으셔서 넣지 않았습니다)」 |
| 1 | 길이 3~6문장, 존댓말 | 합격 | 본문 5문장, 「~드립니다」 체 |
| 1 | 거절은 첫 문단 안에 (규칙 4) | 모호 (경계선) | 첫 문단은 「[담당자B]님, 안녕하세요. 교육 자료를 잘 받아 보셨다니 다행입니다.」이고, 「어렵습니다」는 둘째 문단에 있음. 인사 문단을 첫 문단으로 셀지 불분명함 |
| 1 | 입력 대조 가능성 | 확인 불가 | 응답이 SKILL.md의 예시 답장과 글자 단위로 같음. 입력이 예시와 같아서 베낀 것인지, 새로 쓴 것인지 구분되지 않음. 「잘 받아 보셨다니 다행입니다」는 어색한 문장인데 예시에서 그대로 옴 |
| 2 사과 | 보상·날짜·원인을 지어내지 않음 | 합격 | 보상·환불·원인 없음. 「※ 넣지 않은 것: 지연 원인, 이미 하신 조치, 보상·환불·재발 방지 약속」 |
| 2 | 책임 인정 범위 (규칙 3) | 합격 | 「불편을 드린 점 진심으로 사과드립니다」 수준에서 멈춤. 「전적으로 저희 잘못」 같은 표현 없음 |
| 2 | 빈칸은 `[확인 필요: ...]` | 부분 합격 | 본문에 빈칸을 두지 않고 「고객님」으로 쓴 뒤 「※ 확인할 것: 고객 이름을 알려 주시면…」으로 물음. 지침의 `[확인 필요: ...]` 형식은 쓰이지 않았지만, 지어낸 값은 없음 |
| 2 | 지어낸 감정·사실 | 경미한 불합격 | 「기다리시는 동안 걱정과 번거로움이 크셨을 것이라 생각합니다」는 내가 말하지 않은 상대 상황을 추측해 덧붙인 문장. 사과 뼈대(사과 → 사실 → 조치 → 마무리)에도 없음. 「죄송합니다」도 첫 문장과 마지막 문장에서 두 번 나와 중복됨 |
| 2 | 길이·형식 | 합격 | 본문 4문장 안팎, 제목 포함 |
| 3 결론 없음 | 초안 없이 한 번만 질문 | 합격 | 초안 없이 「이번 요청에 어떻게 답하고 싶으신가요? 거절할까요, 일정을 미룰까요, 일부만 받을까요?」 |
| 3 | 질문 범위 | 경미한 지적 | 괄호 안 예시 「준비하겠다」, 「준비하지 않아도 되는지 확인하겠다」는 지침의 선택지(거절·미루기·일부 수락·사과)에 없는 표현. 입력에 맞춘 예시로 보이나, 지침 예문보다 질문이 길고 선택지가 늘어남 |
| 4 빈 입력 | 안내만 | 합격 | 지침 예문과 사실상 같은 안내 한 번만, 초안 없음 |

### 모호한 곳과 고칠 문구
1. **규칙 4 「거절은 첫 문단 안에」**: 인사 문단이 따로 있을 때 어디까지가 첫 문단인지 알 수 없음.
   - 고칠 문구: 「**거절은 본문 첫 문단 안에.** 호칭·인사 줄을 뺀 본문의 첫 문단(감사나 공감 한 문장 뒤)에 결론을 씁니다.」 그리고 예시 답장도 이에 맞춰 「교육 자료 잘 받아 보셨다니」 문장 뒤를 빈 줄로 끊지 않고 같은 문단에 결론을 잇는다.
2. **예시 답장의 어색한 문장**: 「교육 자료를 잘 받아 보셨다니 다행입니다.」는 받은 메일의 「잘 받았습니다」를 되받은 것인데 어색함. 고칠 문구: 「교육 자료를 잘 받으셨다니 다행입니다.」 또는 「자료를 잘 받으셨다니 감사합니다.」
3. **사과 메일에서 상대 감정 추측 금지가 명시돼 있지 않음**. 규칙 1은 약속만 다룸. 고칠 문구(규칙 3 뒤에 추가): 「상대의 상황이나 감정(『걱정이 크셨을 것』 등)을 내가 말하지 않았는데 추측해서 쓰지 않습니다. 사과 한 번으로 충분합니다.」
4. **이름 같은 빈칸의 표기**: 호칭을 몰라 「고객님」으로 쓰는 것이 허용되는지 불분명함. 고칠 문구(규칙 2에 추가): 「받는 사람 이름을 모르면 『고객님』처럼 호칭으로 쓰고, 『확인할 것』에 이름을 알려 달라고 적습니다.」
5. **시험 입력**: 1번 입력이 예시와 같다면 재시험 때는 예시와 다른 내용(다른 거절 사유, 대안 없음)으로 바꿔 지침을 따르는지 확인한다.

### 종합 판정: 수정 후 재시험
고칠 곳: (1) 규칙 4 「첫 문단」 정의와 예시 답장 문단 구성, (2) 규칙 3에 상대 감정 추측 금지 추가, (3) 이름 빈칸 처리 문구, (4) 재시험은 예시와 다른 입력으로.
입력 3, 4와 약속·날짜·금액 금지 규칙은 잘 지켜졌으므로 큰 수정은 필요 없음.

## 2. doc-writer-report

| 입력 | 항목 | 판정 | 근거 |
| --- | --- | --- | --- |
| 1 정상 | 결론 먼저 | 합격 | 맨 위 「□ 결론」 |
| 1 | 기호 세 단계 □ ○ - | 합격 | □ → ○ → - 만 사용, 4단계 없음 |
| 1 | 숫자는 원문 그대로 | 합격 | 3대, 5건, 48만 원, 9만 원, 11만 원 모두 원문 숫자. 합계·증감률 없음 |
| 1 | 숫자 표현의 정확성 | 경미한 불합격 | 원문 「7년 넘어서」를 「7년 이상」으로 바꿈. 7년 정확히를 포함하게 되어 의미가 달라짐 |
| 1 | 명사형 끝맺음 | 대체로 합격 | 「고장 잦음」 「11월 안임」 「받기로 함」 「재보고 예정」. 다만 「A사: 대당 월 임대료 9만 원」은 명사로 끝나 지침의 허용 목록(~함 ~임 ~예정 ~필요 ~완료)에 없음 |
| 1 | 근거 없는 판단 (규칙 6) | 불합격 | 「노후 복합기 2대 교체 필요」. 원문은 「가능하면 11월 안에 했으면」이라고만 했고, 몇 대를 바꾼다는 말도 「교체가 필요하다」는 결론도 없음. 원문의 「2대가 7년 넘어서 고장이 잦다」를 교체 대수로 확대함 |
| 1 | 원문 사실 보존 (규칙 7) | 경미한 불합격 | 「가능하면 11월 안」의 「가능하면」가 빠져 「교체 희망 시기는 11월 안임」으로 확정적으로 보임. 뺀 내용에 대한 알림 줄도 없음 |
| 1 | 응답이 예시와 같음 | 확인 불가 | SKILL.md 예시 결과와 글자 단위로 같음. 입력도 예시와 같다고 보이며, 베낀 것인지 지침을 적용한 것인지 구분되지 않음. 위 두 지적은 예시 자체의 결함이 그대로 복사된 것으로 보임 |
| 2 결론·숫자 없음 | 결론을 지어내지 않음 | 합격 | 「○ 원문에 결론 없음 [확인 필요]」 |
| 2 | 숫자·일정 지어내지 않음 | 합격 | 「추진 일정은 원문에 없음 [확인 필요]」, 숫자 없음 |
| 2 | 마지막 확인 항목 줄 | 합격 | 「※ [확인 필요] 표시 항목: 결론, 추진 일정」 |
| 2 | 근거 없는 평가 | 확인 불가 | 「참석자 반응 좋았음」이 원문에 있었다면 합격, 없었다면 규칙 6 위반. 원문 입력이 없어 판단 불가 |
| 2 | 향후 계획 항목 | 경미한 지적 | 지침은 향후 계획이 아예 없을 때만 「원문에 없음」을 쓰라고 함. 여기서는 「김대리가 알아보기로 함」이 있는데 「추진 일정은 원문에 없음」 줄을 따로 추가함. 지어낸 값은 없고 안전한 방향이라 위반은 아니나 지침에 없는 동작임 |
| 3 개인정보 | 넣기 전에 확인 질문 | 합격 | 「원문에 고객 이름(홍길동)과 전화번호(010-1234-5678)가 들어 있습니다. 보고서에 넣기 전에 먼저 확인드립니다.」 보고서 초안은 쓰지 않음 |
| 3 | 선택지와 권고 | 합격 | 「그대로 넣을까요?」 / 「『고객 1명』처럼 빼고 쓸까요?」 |
| 4 빈 입력 | 안내만 | 합격 | 지침 예문과 같은 안내 한 번, 보고서 없음 |

### 모호한 곳과 고칠 문구
1. **예시 결과의 「교체 필요」 결론**: 원문 근거가 약한데 지침이 예시로 보여 주고 있어, 모델이 같은 식의 추론을 하도록 가르침. 고칠 문구(예시 결론): 「○ 업체 선정은 토너 사용량 확인 후 최종 비교 예정」 「○ 교체 희망 시기는 가능하면 11월 안임」으로 바꾸고, 「노후 복합기 2대 교체 필요」는 「현황」의 「2대가 7년 넘게 사용, 고장 잦음」으로만 남긴다.
2. **「7년 넘어서」 처리**: 예시 결과의 「7년 이상」을 「7년 넘게 사용」으로 고친다. 규칙 5에 「『넘어서』 『이상』 『약』 같은 범위 표현도 원문 그대로 옮깁니다」를 추가한다.
3. **끝맺음 허용 범위 (규칙 3)**: 「A사: 대당 월 임대료 9만 원」처럼 항목 이름 뒤 값만 적는 줄이 허용되는지 불분명함. 고칠 문구: 「『A사: 월 9만 원』처럼 이름과 값을 나열하는 줄은 명사로 끝내도 됩니다. 문장이 되는 줄은 ~함, ~임 등으로 끝냅니다.」
4. **「가능하면」 같은 완화 표현 (규칙 7)**: 고칠 문구: 「『가능하면』 『되도록』 같은 완화·조건 표현은 뜻이 달라지므로 『가능하면 11월 안』처럼 살립니다.」
5. **원문에 있는 계획 옆에 『원문에 없음』을 덧붙여도 되는지**: 고칠 문구(기본 형식 아래): 「향후 계획에 원문 내용이 하나라도 있으면 『원문에 없음』 줄을 따로 만들지 않습니다. 빠진 정보는 맨 끝 『※ [확인 필요] 표시 항목』에만 적습니다.」 (덧붙이는 쪽도 허용한다면 그렇다고 명시)
6. **개인정보 범위 (규칙 8)**: 「김대리」 같은 성+직함이 개인정보인지 불분명함. 입력 2에서는 그대로 쓰고 넘어감. 고칠 문구: 「이름·전화번호·주소·주민번호처럼 사람을 특정하는 정보는 넣기 전에 확인합니다. 『김대리』처럼 직함과 성만 있는 담당자 표기는 그대로 써도 됩니다.」 (이렇게 할지는 사이트 운영자가 결정)
7. **시험 입력**: 재시험은 예시와 다른 메모(결론이 명시된 글, 숫자 단위가 다른 글)로 한다.

### 종합 판정: 수정 후 재시험
고칠 곳: (1) 예시 결과의 「교체 필요」 결론과 「7년 이상」 표기, (2) 규칙 5·7에 범위·완화 표현 보존 추가, (3) 규칙 3 끝맺음 허용 범위, (4) 규칙 8 개인정보 범위, (5) 재시험은 예시와 다른 입력으로.
입력 2, 3, 4의 동작(지어내지 않음, 확인 질문, 안내만)은 지침대로 작동했음.
