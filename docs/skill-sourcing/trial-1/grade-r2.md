# 시험 실행 2회차 채점 (grade-r2)

채점 기준은 각 스킬의 `SKILL.md` 지침입니다. 입력 원문은 과제에 적힌 것을 기준으로 했습니다. 실행 결과 파일의 "입력 요약"에만 있고 원문에는 없는 내용(예: 받은 메일의 제목, 요일)은 대조할 수 없어서 "확인 불가"로 따로 적었습니다.

## 1. email-reply

| 입력 | 항목 | 판정 | 근거 |
| --- | --- | --- | --- |
| 1 일정 미루기 | 뼈대(사과 → 바뀐 일정 → 이유 → 마무리) | 합격 | 「좋지 않은 소식을 전하게 되어 죄송합니다. 이번 주 금요일로 예정되어 있던 납품이 다음 주로 미뤄지게 되었습니다.」 |
| 1 | 날짜를 지어내지 않음, 빈칸 표기 | 합격 | 「정확한 납품일은 [확인 필요: 날짜]입니다」, 끝에 「※ 확인할 것」 |
| 1 | 이유는 준 것만 | 합격 | 「부품 입고가 늦어진 것이 이유입니다」 |
| 1 | 약속·보상 덧붙임 없음, 뺀 것 표시 | 합격 | 「※ 넣지 않은 것: 날짜 확정 후 다시 안내하겠다는 약속, 보상이나 대체 방안」 |
| 1 | 길이 3~6문장, 존댓말 | 합격 | 본문 5문장 |
| 1 | 사과 한 번 (규칙 3) | 경미 | 「죄송합니다」 뒤에 「거듭 양해 부탁드립니다」가 한 번 더 나옴. 사과 표현이 아니라 양해 요청이고 문장 수도 맞아 위반으로 보지는 않음 |
| 2 거절(불참) | 거절이 본문 첫 문단 안에, 감사 뒤 바로 결론 (규칙 4) | 합격 | 「워크숍 안내 감사합니다. 이번 토요일 워크숍에는 개인 일정으로 참석하기 어렵습니다.」 (호칭·인사 줄 다음 첫 문단) |
| 2 | 이유는 준 것만, 대안 없음 | 합격 | 「개인 일정으로」만 씀. 「※ 넣지 않은 것: 대체 참석이나 사후 공유 같은 대안」 |
| 2 | 길이·존댓말 | 합격 | 본문 3문장, 「~어렵습니다」 체 |
| 2 | 입력에 없는 정보 | 확인 불가 | 과제 원문은 「주말 워크숍」인데 응답은 「이번 토요일」. 받은 메일에 있던 요일이면 문제 없음. 받은 메일 원문이 없어 판단 불가 |
| 3 실수 사과 | 사과 → 사실 → 조치 → 마무리 | 합격 | 「요청하신 것과 다른 파일을 보내 드려 죄송합니다. 오늘 중으로 맞는 파일을 다시 보내 드리겠습니다.」 |
| 3 | 상대 감정 추측 없음, 사과 한 번 (규칙 3) | 합격 | 「걱정이 크셨을 것」류 문장 없음. 사과는 한 번 |
| 3 | 이름 모름 처리 (규칙 2) | 합격 | 호칭 「고객님」 + 「※ 확인할 것: 받는 분 이름을 알려 주시면…」 |
| 3 | 약속 덧붙임 없음 | 합격 | 「오늘 중 재발송」은 입력에 있음. 「※ 넣지 않은 것: 재발 방지 약속, 오류 원인 설명」 |
| 4 결론 없음(「알아서」) | 가장 보수적인 안으로 쓰고 그렇게 썼다고 알림 (하는 일 3) | 합격 | 「결론을 따로 정해 주지 않으셔서, 가장 보수적인 안(확답 없이 내부 확인 후 회신)으로 썼습니다.」 |
| 4 | 수락·거절·날짜를 정하지 않음 | 합격 | 「확인이 끝나는 대로 회신드리겠습니다.」 날짜 없음. 「※ 넣지 않은 것: 회신 날짜, 수락이나 거절 의사」 |
| 4 | 이름 모름·결론 후속 안내 | 합격 | 「이번 주 안에 답할 수 있는지, 수락·거절 등 결론이 정해지면 알려 주세요」 |
| 공통 | 초안을 보여 주고 고칠 곳 질문, 대신 보내지 않음 | 합격 | 4건 모두 「고칠 곳이 있으면 말씀해 주세요. 메일은 직접 보내셔야 합니다.」 |
| 공통 | 받은 메일 제목 | 확인 불가 | 「RE: 납품일 확인 요청」 「RE: 주말 워크숍 참석 안내」 등은 과제 원문에 제목이 없음. 받은 메일에 있던 제목이면 문제 없음. 만든 제목이라면 형식상 가벼운 문제 |

### 1회차 지적 해결 여부
| 1회차 지적 | 해결 | 근거 |
| --- | --- | --- |
| 규칙 4 「첫 문단」 모호 | 해결 | 입력 2(거절)에서 본문 첫 문단에 감사 → 결론이 바로 옴 |
| 사과 메일에서 상대 감정 추측 | 해결 | 입력 3에 추측 문장 없음, 사과도 한 번 |
| 이름을 모를 때 처리 | 해결 | 입력 3·4 모두 「고객님」 + 「확인할 것」 |
| 예시를 베낀 것인지 구분 안 됨 | 해결 | 이번 입력은 예시와 다르고, 응답도 예시 문장과 다름 |
| 결론 없음/빈 입력 질문 선택지가 늘어남 | 해결 | 입력 4는 지침의 「알아서」 규칙대로 처리 (질문 없이 보수적 안 + 알림) |
| 빈칸을 `[확인 필요: ...]`로 표기 | 해결 | 입력 1 「[확인 필요: 날짜]」 |

### 모호한 곳과 고칠 문구
이번 시험에서 지침의 모호함 때문에 생긴 문제는 없었습니다. 억지로 고칠 곳을 만들지 않습니다.

### 종합 판정: 합격
약속·날짜·이유·감정 지어내기 방지, 첫 문단 거절, 보수적 안 처리가 4건 모두 지침대로 나왔고 1회차 지적도 모두 해결됨.

## 2. doc-writer-report

| 입력 | 항목 | 판정 | 근거 |
| --- | --- | --- | --- |
| 1 서버 교체 | 결론 먼저, 원문에 있는 것만 | 합격 | 「서버를 클라우드로 이전하기로 결정함」 「12월 말까지 완료 예정」 (원문에 있음). 「교체 필요」 같은 추론 결론 없음 |
| 1 | 숫자·범위 표현 그대로 (규칙 5) | 합격 | 「약 40대 중 12대가 5년 넘게」 「월 약 300만 원」 「연 4천만 원 정도」. 연 환산·차액 계산 없음 |
| 1 | 완화 표현 보존 (규칙 7) | 합격 | 「보안 검토는 되도록 11월 중 완료 예정」 |
| 1 | 담당 보존, 기호 세 단계, 명사형 끝맺음 | 합격 | 「담당: 이과장」 / □ ○ - 만 사용 / 「~함」 「~예정」 「월 약 300만 원 예상」 |
| 1 | 원문 단어 보존 | 경미 | 원문 「추정」을 「예상」으로 바꿈. 뜻은 같고 숫자도 그대로라 불합격으로 보지 않음 |
| 1 | `※ [확인 필요] 표시 항목` 줄 | 경미한 불합격 | 지침은 「없으면 이 줄 생략」인데 「※ [확인 필요] 표시 항목: 없음」을 씀 |
| 2 매출·광고비 | 숫자 지어내지 않음, 증감률 없음 | 합격 | 「이번 달 매출이 지난달보다 늘었음」, 수치·% 없음 |
| 2 | 결정 사항을 지어내지 않음 | 합격 | 「광고비 증액 여부는 다음 회의에서 결정 예정」 |
| 2 | 담당·요청자 보존 | 합격 | 「마케팅팀 박팀장: 광고비 증액 요청」 (직함+성은 그대로 써도 됨, 규칙 8) |
| 2 | 근거 없는 판단 없음 | 합격 | 「매출 증가로 증액 타당」 같은 연결 판단 없음 |
| 2 | 향후 계획에 「원문에 없음」 줄 | 합격 | 계획 항목이 있어서 「원문에 없음」 줄을 따로 만들지 않음 (1회차 지적 해결) |
| 2 | 수치 없음 표시 | 경미 | 「구체 수치는 아직 없음 [확인 필요]」. 지침은 「숫자가 없으면 숫자 없이 씀」인데 확인 필요 줄을 추가함. 지어낸 값은 없고 끝 「※ [확인 필요] 표시 항목」과 일치해 안전한 방향이라 위반으로 보지 않음. 「아직」은 약간 덧붙인 표현 |
| 3 신입(이름·주소) | 개인정보 확인 질문 (규칙 8) | 합격 | 「원문에 이름(김민수)과 주소(서울시 강남구 테헤란로 1)가 들어 있습니다. 보고서에 이 개인정보를 그대로 넣어도 될까요?」 |
| 3 | 초안을 쓰지 않고 한 번만 질문, 대안 제시 | 합격 | 보고서 초안 없음. 「이름은 『신입 입사자』로 바꾸고 주소는 뺀 채로 정리하겠습니다」 |
| 4 회사 양식 | 양식을 따름 | 합격 | 「□ 1. 목적」 「□ 2. 내용」 「□ 3. 건의사항」 순서대로 |
| 4 | 원문에 없는 항목 안 만듦, 없음도 표기 | 합격 | 「□ 3. 건의사항 ○ 없음」 (원문에 「건의사항 없음」이 있음) |
| 4 | 숫자·일정 그대로 | 합격 | 「비용: 12만 원」 「업체 방문: 다음 주 금요일 예정」 |
| 4 | 원문에 없는 말 추가 | 확인 불가 | 응답의 「사무실 정수기」 「교체 필요」는 과제 원문(「정수기 필터 교체」)에 없음. 실행 요약에는 「사무실 정수기 필터 교체 필요」로 적혀 있어 입력에 있었을 가능성이 큼. 원문 대조가 안 되어 판정 보류 |
| 4 | `※ [확인 필요] 표시 항목` 줄 | 경미한 불합격 | 입력 1과 같이 「※ [확인 필요] 표시 항목: 없음」을 씀 (「없으면 이 줄 생략」) |

### 1회차 지적 해결 여부
| 1회차 지적 | 해결 | 근거 |
| --- | --- | --- |
| 근거 없는 「교체 필요」 결론(규칙 6, 9) | 해결 | 입력 1은 원문이 말한 결정(클라우드 이전, 12월 말)만 결론에 씀 |
| 「넘어」를 「이상」으로 바꿈 | 해결 | 「5년 넘게」 그대로 |
| 「가능하면」「되도록」 같은 완화 표현 누락 | 해결 | 「되도록 11월 중」 보존 |
| 「A사: 월 9만 원」류 끝맺음 허용 범위 | 해결 | 「클라우드 이전 시: 월 약 300만 원 예상」 「담당: 이과장」 형식을 쓰고 문제 없음 |
| 계획이 있는데 「원문에 없음」 줄을 덧붙임 | 해결 | 입력 2에서 덧붙이지 않음 |
| 개인정보 범위(규칙 8): 직함+성 | 해결 | 「이과장」 「박팀장」은 그대로 쓰고, 이름·주소는 질문 |
| 예시를 베낀 것인지 구분 안 됨 | 해결 | 입력이 예시와 다르고 응답도 예시와 다름 |
| 1회차에 없던 새 문제 | 있음(경미) | 위 표의 「표시 항목: 없음」 줄 |

### 모호한 곳과 고칠 문구
1. **`※ [확인 필요] 표시 항목` 줄 생략 규칙**: 입력 1, 4에서 「없음」이라고 적음. 생략 조건이 코드 블록 안 괄호 설명에만 있어서 모델이 템플릿 줄을 그대로 옮긴 것으로 보임. 필수 수정은 아니며 보완 권장.
   - 고칠 문구(기본 형식 아래 설명에 추가): 「`※ [확인 필요] 표시 항목` 줄은 [확인 필요]를 붙인 곳이 하나라도 있을 때만 씁니다. 하나도 없으면 『없음』이라고 쓰지 말고 줄 전체를 쓰지 않습니다.」
2. 그 밖에는 지침 모호함으로 인한 문제 없음.

### 종합 판정: 합격
핵심 규칙(숫자·범위 표현 보존, 완화 표현, 추론 결론 금지, 개인정보 확인, 양식 따르기)이 4건 모두 지켜졌고 1회차 지적은 모두 해결됨. 위 1번 문구 보완은 권장이며 재시험이 꼭 필요한 수준은 아님.

## 남은 위험 (시험으로 확인하지 못한 것)
- 입력이 각 스킬 4건뿐이라 규칙 전체를 덮지 못함. email-reply는 「재촉」 「범위 밖 요청」 뼈대와 윗사람·동료별 말투 차이를, doc-writer-report는 긴 원문, 문제점·요청 사항이 함께 있는 글, 원문에 결론이 없는 경우(`원문에 결론 없음 [확인 필요]`)를 이번에는 시험하지 못함.
- 입력 원문과 받은 메일 전문이 실행 결과 파일에 없어서, 응답의 요일(「이번 토요일」), 받은 메일 제목, 「사무실」 「교체 필요」 같은 표현이 입력에 있었는지 대조하지 못함. 재시험 때는 입력 전문을 결과 파일에 함께 남기면 정확히 채점할 수 있음.
- 같은 모델이 이 시험의 실행자와 채점자였기 때문에 모델 편향이 있을 수 있음. 다른 모델(예: Claude 앱에서 다른 요금제/모델, Codex 등)에서 같은 입력이 같은 결과를 내는지는 미확인.
- 한 입력당 1회 실행이라 같은 입력에서 결과가 흔들리는지(재현성)는 모름. 특히 개인정보 확인 질문과 「알아서」 처리는 실행마다 달라질 수 있음.
- 실제 Claude 앱·Claude Code에 스킬 파일을 설치해 `/스킬이름`으로 부르는 흐름(설치 경로, 재시작 여부)은 이 시험의 범위가 아니며 `[확인 필요]` 상태 그대로임.
- 한글 생성 문장의 자연스러움(예: 입력 1의 「정확한 납품일은 [확인 필요: 날짜]입니다」)과 실제 회사 문서 관행에 맞는지는 비개발자 사용자 테스트로만 확인 가능.
